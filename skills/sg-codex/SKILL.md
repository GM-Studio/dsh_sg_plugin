# SpecGate 使用向导（从这里开始）

统一导航按用户意图转接一项能力；先读取对应 Skill，不复制独立执行流程。用户可见说明、表单和错误解释使用中文，准确保留路径、版本、命令。

| 用户意图                                             | 入口                |
| ---------------------------------------------------- | ------------------- |
| 环境自检、缺工具、按需安装、诊断修复                 | `$sg-codex-env`     |
| 新建/初始化、接入存量项目、项目 Agent/Skill/MCP 配置 | `$sg-codex-project` |
| 新增、修改、修复、继续/暂停/取消任务、验收交付       | `$sg-codex-change`  |
| 当前项目、技术栈、进度、阻塞、待审批、最近交付       | `$sg-codex-status`  |

没有明确操作请求时，先只读 `sg_status` 展示状态和入口，必要时澄清。查询状态或帮助不构成安装、初始化、恢复或开发授权。用户请求环境准备就停在环境结果；项目就绪但没有业务需求就等待。不能编造示例需求或代替用户审批。

项目准备和需求开发按需使用同一环境门禁。先预检、复用，仅安装选中技术栈的缺项并真实验证。用户已有明确需求时保留原文并转入需求开发；不能忽略原需求，也不能越过前置门禁。

SpecGate MCP 是项目、审批、证据和交付的权威状态源，禁止手改状态、事件链、冻结哈希和交付记录。只有真实命令和可信审批证据可标记通过。旧 `$sg-codex-setup` 仅作准备兼容转接，不让用户手工连续调用多个 Skill 或重复初始化。
