# sp-skill-brainstorming

## 何时使用

需求含糊、涉及多个能力、验收标准超过 5 条，或用户只给了方向没有给边界时。

## 方法

1. **一次只问一个问题**，等回答再问下一个；不要一次抛出问题清单。
2. 先发散：列出至少两个可行方向与各自代价，不要急着收敛。
3. 再收敛：让用户选方向，或给出一个默认并说明理由。
4. 把结论写成可验证的 AC；写不出 AC 的方向直接丢弃。
5. 在 H1 批准前不写 design、不写代码。

## 检查清单

- [ ] 问题一次只问一个
- [ ] 至少两个方向被比较过
- [ ] 每个 AC 都能写出测试
- [ ] 非目标被明确写出
- [ ] 用户确认了方向，而不是只确认了措辞

## 反模式

- 把“ brainstorm” 变成一次性问卷
- 用“都可以”“看情况”收尾
- 在需求没冻结时开始设计
