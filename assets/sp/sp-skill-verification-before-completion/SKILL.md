# sp-skill-verification-before-completion

## 何时使用

任何“完成/通过/修好了”的说法出现之前，尤其是进入 H3 之前。

## 方法

1. 重新执行验证命令，不引用上一次的输出。
2. 贴出命令、退出码、通过/失败数，以及失败时的原始尾部。
3. 逐条对照 AC：哪条 AC 由哪个用例证明。
4. 有 skip、有未覆盖 AC、有未解释的警告时，不许说“通过”。
5. 列出仍然存在的风险与未验证项。

## 检查清单

- [ ] 命令是本次重新执行的
- [ ] 退出码与用例数都记录
- [ ] 每个 AC 都有对应用例
- [ ] skip/todo 被单独说明
- [ ] 遗留风险写进了验收报告

## 反模式

- “应该能通过”
- 复用缓存的测试结果
- 用“测试大部分通过”替代退出码
