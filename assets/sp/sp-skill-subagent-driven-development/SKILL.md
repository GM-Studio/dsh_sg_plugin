# sp-skill-subagent-driven-development

## 何时使用

把一个已冻结的任务派发给子 Agent 实现时。编排器与子 Agent 之间只有三类可信输入：commit、文件、命令输出。

## 方法

1. 任务提示必须自包含：change、任务 id、AC、允许写的路径、完成标准。
2. 明确要求“完成后提交”，并让子 Agent 回报 commit hash。
3. **不要相信子 Agent 的文字结论**：读 commit、跑 diff 校验、跑测试，三者都过才算完成。
4. 失败时把失败证据（diff 违规、测试输出尾部）带进下一次提示，而不是只说“再试一次”。
5. 子 Agent 不负责合并；合并只由编排器做。

## 检查清单

- [ ] 提示里写清了允许与禁止的路径
- [ ] 有 commit 且 diff 校验通过
- [ ] 测试由编排器执行，而不是复用子 Agent 的自述
- [ ] 失败证据进入下一轮提示
- [ ] 子 Agent 没有执行合并

## 反模式

- 让子 Agent 合并或打 tag
- 只看“已完成”的回复就标记 `[x]`
- 提示里不带 AC，让子 Agent 猜需求
