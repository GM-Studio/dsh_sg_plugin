## 🎯 使用指南

### 原型设计流程

```
明确验证目标
  ↓
选择原型类型
  ├─ LOGIC 原型：逻辑/状态模型是否正确？
  └─ UI 原型：外观应该是什么样？
  ↓
遵循 6 条铁律
  1. 从第一天就是可抛弃的
  2. 一条命令运行
  3. 默认无持久化
  4. 跳过打磨（无测试、无错误处理）
  5. 每次操作后展示完整状态
  6. 完成后删除或吸收
  ↓
知识沉淀
  └─ 原型答案记录到耐久位置（commit message、ADR、Issue）
```

### 经验沉淀时机

- ✅ 完成复杂功能后
- ✅ 解决棘手问题后
- ✅ 发现新的最佳实践
- ✅ 遇到重要教训和陷阱
