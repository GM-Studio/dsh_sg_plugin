# ADR：单人全栈 sg-init 与有效 req 基线

- 日期：2026-10-20
- 范围：已确认的 sg-init 最小化需求 v0.2；直接源码实施，不为本次开发创建 SG 工作流包。

## 固定首版

新建 Java 8、Spring Boot 2.7.18、Maven、H2 文件库后端与 Vue 3、Vite、TypeScript、npm 前端，仅 Item(id/name) CRUD。示例可删除，不是后续业务必须继承的模型。不接管已有工程、不扩充模板、不全局安装、不下载工具链。

默认 full 走 minimal-init.js 的专用安全执行器；显式 minimal/adopt/v3 兼容旧功能，但不绕过其宿主批准。旧多模板 full 生成器不再作为公开默认执行链。

## 确认与文件保护

只读工具白名单探测 → 三轮澄清 → 完整方案预览 → 宿主明确批准 → 重新检查 → 独占创建 → 安装/验证 → 发布基线。

草稿、req、SG 配置、报告在批准前不落盘。计划绑定会话、目标快照、所有模板内容 hash、具体版本及工具路径。批准对象不可由模型伪造且单次消费。yes 无法跳过。目标变化、版本变化、覆盖冲突、链接路径均停止；每次创建使用 wx。不覆盖已有文件，允许保留无关文件。不自动回滚或在半生成项目续跑。

## 严格验收

项目依赖安装、后端真实 H2 测试、前端基本测试、前后端构建、固定端口实际启动、真实浏览器 CRUD/错误反馈、正常重启数据保留和自有进程清理全部通过。浏览器使用已装引擎，不偷偷下载或以 mock/HTTP-only 替代。安装10分钟、构建测试5分钟、启动90秒上限。不自动杀端口占用者，不自动换端口。验证专用关闭功能仅随机 token 开启，用于确认正常关闭而非强杀冒充正常重启。

文件生成不等于验收完成。失败保留内容并报告阶段、原因和下一步；既有用户进程和数据不清理。旧 Java/Boot 组合不承诺生产安全维护。

## 一份有效 req，后续 change 记录差异

初始 openspec/REQ.md 由批准方案直接生成；正文描述批准需求，工程是否已实现由 projectReq 状态和验证证据表达。验收及证据保存完成后才登记有效基线，无需额外初始完成弹窗。失败不能进入正常业务 change。

后续 change 引用当前有效 req，不逐层继承第一份 req。一个项目一个活动 change，记录起始版本、内容标识和路径；手工改动时停止，不自动合并。目标先在 change 中记录，验收通过并经完成关卡确认后替换有效 req，版本递增并关联 change。root 是唯一有效基线，side 通过 projectReqRoot 引用，不以过期副本判断需求。

## 同步失败

有效 req 更新失败进入 BASELINE_PENDING_SYNC，旧基线保留，阻止下一项变更，不重复跑代码或自动归档 Git。同会话内已批准内容、位置和旧基线未变时仅允许最多2次显式同步重试；会话重启或对象变化需重新展示并确认。状态不确定时阻断，不宣告完成。

## Git 与部署边界

本初始化链不自动 Git 提交或新增业务 change；原后续任务执行器的 Git/worktree 前提仍独立存在，运行前需用户明确准备。托管有效基线项目完成后不调用旧自动 Git 归档路径。源码变更不等于当前 DSH 进程已热加载，新会话/宿主重载及真实集成验收需分别确认。

## 本机真实验证未通过项

2026-10-20 的独立生成工程：依赖安装、Java 8 后端构建、Vue 类型检查与构建、真实 H2 文件库测试、前端测试、实际启动、真实 Chrome CRUD/非法输入、正常关闭及重启后读取记录均通过。但重启后的删除及探针数据清理失败，H2 SQLState 90097（只读），总体验收失败，未将该验证工程宣告初始化完成。

同一 Java 8 文件权限探测：File.canWrite=true、RandomAccessFile 的 rw 打开成功、Files.isWritable=false。H2 2.1.214 对已有文件使用 NIO 可写检查，误判后切为只读；ACCESS_MODE_DATA=rw 也不消除这个检查。当前证据指向 Windows/Harness 权限检查兼容问题，不以内存库、私有文件系统 hack、改版本或强制通过绕开。自有服务进程已退出、端口释放，测试数据和证据保留。权限修复不属于初始化自动执行范围，未修改系统权限。
