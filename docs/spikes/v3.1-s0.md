# v3.1 S0 环境探测结论

- 日期：2026-10-19
- 机器：Windows，Node `v24.14.0`，npm `11.9.0`

## 1. 版本管理器

| 工具 | 结果 |
|---|---|
| volta | 缺失 |
| fnm | 缺失 |
| nvm-windows | 存在：`D:\Program Files\nvm\nvm.exe`；已安装 Node 仅 `18.19.0` |
| asdf | 缺失 |

**结论**：本机只能走 nvm-windows。nvm-windows 的 `nvm use` 是**全局切换**（改 `C:\Program Files\nodejs` 链接），不满足“只影响子进程”的要求。

**降级方案**：不调用 `nvm use`，而是读取 `NVM_HOME` 下的版本目录（如 `D:\Program Files\nvm\v18.19.0`），把该目录前置到子进程 `PATH`。这样无需管理员权限、不影响当前会话。实现时若 `NVM_HOME` 不存在则回退到 `nvm root` 查询。

## 2. Python

| 项 | 结果 |
|---|---|
| PATH 上的 `python` | Anaconda `3.13.5` |
| `py -3.12` | `3.12.10` |
| `py -3.14` | `3.14.x`（不在 3.9–3.13 范围） |
| `python3` / `python3.x` 命令 | 不存在（Windows 只有 `py` 启动器） |
| uv | `0.11.2` |
| poetry | 缺失 |
| pytest | `8.3.4`（Anaconda 环境） |

**结论**：Windows 上解释器选择必须优先 `py -3.x`，POSIX 用 `python3.x`；`python3` 在 Windows 不可依赖。3.14 超出支持范围，配置要求 3.9–3.13 时必须拒绝 3.14。

## 3. 包管理器

| 生态 | 可用 | 缺失 |
|---|---|---|
| Node | npm 11.9.0、pnpm | yarn、bun |
| Python | pip、uv | poetry |

**结论**：`yarn`/`bun`/`poetry` 在本机不可用，对应安装分支只能靠单测 mock 验证；真实演示用 npm/pnpm + pip/uv。

## 4. pytest junit-xml

实测：一个 pass、一个 fail 的 pytest 运行生成了 `report.xml`，`testcase` 的 `name` 与 `classname` 可读，failure 节点可判定。

**结论**：适配器可按 `name` 提取 `[AC-xxx]`、按 failure/error/skipped 判状态，不需要第三方插件。

## 5. 对实现的直接影响

1. Node 切换必须实现“nvm-windows 目录前置 PATH”的路径，不能只依赖 `nvm use`；
2. Python 解释器探测要先 `py -3.x -V`，再回退 `python3.x`；
3. 缺工具（volta/fnm/poetry/yarn）时按需求 fail-closed 或给出明确错误，不静默使用宿主默认；
4. 本机 Python 3.13 在范围内，可用于 Python 后端真实演示；3.14 仅作越界负向用例。
