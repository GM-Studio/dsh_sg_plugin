## 0. 计划原则

1. **先安全边界，后功能扩展。** 不在远程认证、数据边界和决策绑定未成立前开放公网控制面。
2. **先纵向闭环，后横向扩展。** 先完成“举手 -> 通知 -> 决策 -> Worker 应用 -> 恢复 -> 再交付”的单 Worker 闭环。
3. **先单 Worker 可靠，后多 Worker 调度。** 第一版只启用一个 Worker，但协议和数据模型支持多个。
4. **每个阶段独立可验收。** 不用后续阶段成功证明前序阶段通过。
5. **验证证据绑定制品。** 所有验收结论必须绑定提交、构建或运行证据；未执行检查如实记录。
6. **保留 Codex 原生执行语义。** 继续使用 approval_policy="never"、SPECGATE_WAITING_FOR_USER、原 session resume。
7. **不把通知当授权。** 消息只负责唤醒，Web 认证与 step-up 才是授权。
8. **不把计划当批准。** 生成计划、任务或代码不等于需求批准或验证通过。

## 2. 目标架构与交付边界

### 2.1 目标拓扑

````text
手机 / 浏览器
     |
   HTTPS
     v
+---------------------------+
| 云端 Web 控制面            |
| Auth / Attention /        |
| Decision / Audit / Outbox |
+-------------+-------------+
              ^
              | 本地主动出站 WSS / 长轮询
              |
+-------------+-------------+
| 本地执行 Worker            |
| Codex / 仓库 / 测试 / 凭证 |
| 完整日志 / 沙箱 / 会话     |
+---------------------------+
`

### 2.2 云端职责

- WebUI、管理 API、认证、设备和会话；
- Project、WorkItem、Run 元数据；
- Attention、Decision、Audit；
- Notification Outbox；
- 脱敏执行摘要与 artifact hash；
- Worker 注册、心跳、租约和项目白名单；
- 决策待应用状态与应用结果。

### 2.3 本地职责

- Codex 执行、仓库、测试、沙箱和完整日志；
- Codex 凭证、SSH key、数据库密码；
- 原始构建产物和完整 diff；
- 原 session 保存与恢复；
- 决策应用前二次校验；
- 失败、取消和回滚的本地执行。

### 2.4 明确禁止

- 云端主动连入本地；
- 云端下发任意 shell；
- 云端保存完整源码、原始日志和 Codex 凭证；
- 消息链接直接建立管理会话；
- IM 内直接审批；
- Worker 令牌复用用户会话；
- 同一 WorkItem 被两个 Worker 同时执行；
- 旧 artifact 的决策应用到新制品。

## 18. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 认证未完成就开放公网 | 管理会话被接管 | M2 作为远程开放硬门禁 |
| 消息链接携带会话令牌 | 转发即授权 | 只发 Attention nonce，不建立会话 |
| 云端保存源码/凭证 | 泄露面扩大 | 数据边界测试和脱敏 fail closed |
| 决策与应用不一致 | 旧批准套新制品 | artifact hash + 版本 + STALE |
| Worker 断线导致重复执行 | 数据损坏 | 租约、幂等、去重、单 Worker 优先 |
| 通知渠道故障 | 漏审批或永久挂起 | Attention 生命周期与渠道解耦 |
| MySQL 单点故障 | 状态丢失 | 备份、binlog、恢复演练 |
| 自动修复循环 | 成本和风险失控 | 轮次、预算、停止条件、Attention |
| AI 修改验收测试 | 自证通过 | 冻结测试、独立验证、变更门禁 |
| 多 Worker 提前复杂化 | 延期和缺陷 | 第一版只启用一个 Worker |

## 19. 变更控制

- 需求变化：重新评估本计划、依赖、验收和退出条件；
- 安全边界变化：必须重新审批，不得在实现中静默降低；
- 新增渠道：通过 Channel Adapter 扩展，不修改 Attention 状态机；
- 新增角色：先扩展授权模型，不直接放宽权限；
- 新增数据库或中间件：必须说明必要性、运维成本和回滚方案；
- 新增多 Worker：不得破坏单 Worker 语义；
- 任何“临时跳过测试”都必须记录，不能标记通过。
````
