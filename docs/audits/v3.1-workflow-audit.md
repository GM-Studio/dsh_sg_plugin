## 仍然存在的边界

- 证据仍是本机文件 + git tag 锚点，不是防篡改审计；需要外部签名时另做。
- implementer 的源码改动仍不要求逐文件列入 touched，只对 docs 强制；这是为了允许实现过程中的合理重构。
- reviewer 是 LLM，不是独立人类审查；人在 H3 看到的是验收摘要 + diff 缩略图。
- 子 Agent 的 cwd 固定在创建时，跨 worktree 复用依赖提示词要求其 `working_directory` 切换，属于软约束。
- AC 唯一性只在 ADDED/MODIFIED 校验；历史归档测试如果保留旧 AC 标签，任务级已按 diff 过滤，但 specs 层仍可能存在同名历史编号，迁移时需一次性清理。

## 建议后续

1. 证据签名或外部时间戳（可选）。
2. 为 implementer 增加“源码 touched 警告”而非硬失败。
3. 归档时为旧 AC 编号做一次迁移/重写工具。

## 新增需求：门禁对话框 UX 与 H0 闭环（2026-10-19 确认）

状态：待批准（本文件即需求文稿，批准后实施）。

### 背景

当前 H1/H2/H3 把最长 6000 字符的 Markdown 直接塞进 `question` 字段，DSH 对话框按原文显示 `#`、`|`、代码块，内容一长就把「通过 / 需要修改」按钮顶出可视区。H0 只是 `/sg-init` 内的确认步骤，没有状态、审批记录、续跑与回退。

### 功能需求

#### FR-1 门禁卡片格式

- H1/H2/H3/H0 一律使用**纯文本紧凑卡片**：不使用 `#`、`|` 表格、代码围栏；使用短行、「键：值」、缩进与分隔线。
- 单次 `question` 正文硬上限 **1200 字符**；超出必须压缩并在末尾给出详情文件路径。
- 布局固定为：标题行、变更元信息、摘要区、列表区（前 N 项）、详情路径、确认提示。
- 中文；数字与 ID 左对齐；不输出原始 JSON。

#### FR-2 分门摘要

- H1：背景 1 行、目标 1 行、REQ 数、AC 数、影响 capability、前 3 个 AC；其余省略。
- H2：任务数/可并行数、前 5 个任务（ID + 标题 + AC）、文件 M/A/D 计数与总行数、套件数、planHash 短码。
- H3：AC pass/fail 计数、失败 AC（最多 3）、测试 total/pass/fail、diff 文件数与 +/− 总计、**1 个最关键文件的 5 行 diff**。
- H0：背景、技术栈、验收标准、团队、实施步骤各 1 行；缺失项与风险各最多 3 条；上下文哈希短码。

#### FR-3 详情文件

- 完整内容写入 `.specgate/gates/H0.txt`、`H1.txt`、`H2.txt`、`H3.txt`，每次门禁重写。
- 详情文件同样脱敏；卡片末尾显示 `详情：.specgate/gates/Hx.txt`。

#### FR-4 H0 状态闭环

- 新增阶段 `H0_PENDING`：`/sg-init` 只做空目录检测、上下文问答、写状态，不建脚手架。
- `approvals.H0` 记录上下文哈希；`/sg-approve H0` 批准；哈希变化则拒绝。
- `/sg-run` 在 `H0_PENDING`：校验 H0 已批准且哈希未变，执行脚手架、产物、git commit、创建首个 change，进入 `H1_PENDING`。
- `/sg-status` 显示 `H0_PENDING`、上下文摘要与下一步。
- 中断可续跑：状态与上下文持久化，重启后继续。

#### FR-5 H0 修改与回退

- 批准前：可反复重问上下文，哈希随之更新。
- 批准后：新增第五个命令 `/sg-context --reset`，清除 `approvals.H0`，回到 `H0_PENDING` 重新问答；已有脚手架不删除，`/sg-run` 时按“已存在则跳过/合并”处理。

#### FR-6 命令面

- 对外命令从 4 个变为 5 个：`/sg-init`、`/sg-change`、`/sg-status`、`/sg-skill`、`/sg-context`。
- `/sg-context --reset` 仅用于 H0 上下文回退；其余参数拒绝。
- `sg_run` / `sg_approve` 仍为模型工具。

### 非功能需求

- **性能**：单次卡片生成 <100ms（本地读取 + 字符串拼接）。
- **确定性**：同一冻结产物生成完全相同的卡片（不含时间戳/随机数）。
- **脱敏**：疑似 secret/token/password/api_key/PRIVATE KEY 的行替换为 `[REDACTED]`。
- **离线**：不依赖网络。
- **安全**：卡片与详情文件都不包含完整密钥；详情文件可被 gitignore。
- **兼容**：H0 之外的存量仓库流程不变；旧状态缺少 `approvals.H0` 时按未批准处理。

### 验收标准

- AC-1：H1/H2/H3/H0 卡片均 ≤1200 字符，正文不含 `#` 标题与 `|` 表格，按钮在常见窗口高度内可见。
- AC-2：每个门禁生成对应 `.specgate/gates/Hx.txt`，内容比卡片完整且已脱敏。
- AC-3：空目录 `/sg-init` → `H0_PENDING`；`/sg-approve H0` → `/sg-run` → 脚手架 + 首个 change → `H1_PENDING`。
- AC-4：H0 未批准时 `/sg-run` 拒绝；批准后改上下文哈希，`/sg-run` 拒绝并要求重新 H0。
- AC-5：`/sg-context --reset` 清除 H0 批准并回到 `H0_PENDING`，可重新问答。
- AC-6：`/sg-status` 在 H0_PENDING 显示上下文摘要与下一步。
- AC-7：单测覆盖卡片字符上限、纯文本格式、详情文件、H0 状态迁移与回退；`node --test` 全绿。
