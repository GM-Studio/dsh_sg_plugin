## 仍然存在的边界

- 证据仍是本机文件 + git tag 锚点，不是防篡改审计；需要外部签名时另做。
- implementer 的源码改动仍不要求逐文件列入 touched，只对 docs 强制；这是为了允许实现过程中的合理重构。
- reviewer 是 LLM，不是独立人类审查；人在 H3 看到的是验收摘要 + diff 缩略图。
- 子 Agent 的 cwd 固定在创建时，跨 worktree 复用依赖提示词要求其 `working_directory` 切换，属于软约束。
- AC 唯一性只在 ADDED/MODIFIED 校验；历史归档测试如果保留旧 AC 标签，任务级已按 diff 过滤，但 specs 层仍可能存在同名历史编号，迁移时需一次性清理。

## 建议后续

1. 证据签名或外部时间戳（可选）。
2. 为 implementer 增加“源码 touched 警告”而非硬失败。
3. 归档时为旧 AC 编号做一次迁移/重写工具。
