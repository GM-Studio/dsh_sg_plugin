# 工具面数字更正（D-06 误判纠正）

日期：2026-10-26
关联：计划 §1.3 D-06、SNA-0808

## 1. 我此前的错误判断

在计划 §1.3 与 `01-binding-matrix.md` 中，我记录了一条「语义漂移」：

> D-06 工具面数字漂移：`CHANGELOG` 声称 43 个工具，源码实存 51 个 `sg_*` 名称。

**这条判断是错的。**

## 2. 实测更正

| 口径                                                               | 数字   | 含义                                             |
| ------------------------------------------------------------------ | ------ | ------------------------------------------------ |
| `createToolRegistry({}).definitions.length`                        | **43** | 默认向用户公开的工具集                           |
| `createToolRegistry({ optionalModules: true }).definitions.length` | **54** | 含可选模块（控制面/安装器/初始化等）             |
| 我此前的正则静态计数                                               | 51     | 把非工具定义（文档字符串、协议描述等）也算进去了 |

`CHANGELOG.zh.md:5` 的「Core v1 默认收敛为 43 个本地工具」**是准确的**，与默认注册表完全一致。

## 3. 错误成因

我当时用的是：

```
grep -rhoE "'sg_[a-z_0-9]+'" src/codex --include=*.js | sort -u | wc -l
```

该正则匹配**任何**引号包裹的 `sg_*` 字符串，包括：

- 工具名（正确的目标）
- 错误码与事件名（如 `'sg_state'` 出现在日志/协议常量中）
- 文档与提示文本中引用工具名的地方

而 `health`、`status`、`version` 三个工具不以 `sg_` 开头，又会被漏掉。两个方向的偏差叠加，得到 51 这个既非公开集也非全集的数字。

## 4. 正确做法

应通过注册表而非源码文本计数：

```
import { createToolRegistry } from './src/codex/workflow-tools.js';
createToolRegistry({}).definitions.length                              // 43
createToolRegistry({ optionalModules: true }).definitions.length       // 54
```

## 5. 影响评估

| 项          | 影响                                                                    |
| ----------- | ----------------------------------------------------------------------- |
| 需求实现    | **无**。D-06 从未驱动任何代码改动；M0–M7 的 15 个新模块与既有工具面无关 |
| 计划文档    | §1.3 D-06 与 §16.3 需要更正（已于本次更新）                             |
| `CHANGELOG` | **不需要改动**。它本来就对                                              |
| SNA-0808    | 原计划的「校正 CHANGELOG 数字」一项取消；改为本文记录更正               |

## 6. 教训

「源码里有几处字符串」不等于「对外暴露几个工具」。对**能力面**的断言必须走注册表或真实调用，不能用文本 grep —— 这与本计划反复强调的「静态观察 ≠ 运行验证」（AC-05）是同一条原则。
