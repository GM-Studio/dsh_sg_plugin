# 部署模式与网络边界

- 日期：2026-10-23
- 状态：**设计基线**
- 结论：飞书/钉钉通知本身不要求 Tailscale、公网 IP、域名或反向代理；它们只需要从云端或 Worker 主动出站访问平台 Webhook。

## 1. 三种部署模式

### 1.1 本地单机模式

```text
浏览器 -> 127.0.0.1 管理端口
本地控制面 -> 本地 Worker/Codex
```

适用：单机开发、离线验证。

安全要求：

- 默认绑定回环地址；
- 不使用远程模式的弱配置；
- 管理端口不暴露到公网；
- 本地凭证不进入云端。

### 1.2 云端 WebUI + 本地主动 Worker

```text
浏览器 --HTTPS--> 云端 WebUI/控制面
本地 Worker --主动 WSS/HTTPS 出站--> 云端
云端 --出站 HTTPS--> 飞书/钉钉 Webhook
```

特点：

- 云端不主动连接本地；
- Worker 使用独立令牌；
- 不需要本地公网 IP、端口映射或反向代理；
- 适合一人团队远程查看和处理 Attention。

### 1.3 私有网络叠加模式

```text
浏览器 --Tailscale/WireGuard--> 云端或本地管理面
```

Tailscale 是可选访问方式，不是飞书/钉钉接入的必要条件。若使用：

- 仍必须启用认证、授权和 step-up；
- 不能把“处于私有网络”当作唯一安全边界；
- 仍需 HTTPS 和安全 Cookie（除非严格限定在受控本地回环场景）；
- 必须明确谁能加入网络。

## 2. 飞书/钉钉接入

### 2.1 不需要的条件

- 不需要公网 IP；
- 不需要域名；
- 不需要反向代理；
- 不需要 Tailscale；
- 不需要开放本地管理端口。

### 2.2 需要的能力

- 能主动出站访问平台 Webhook；
- 能保存并轮换 Webhook 密钥；
- 能对通知内容脱敏；
- 能记录投递结果和重试；
- 消息链接指向云端 WebUI 的 Attention 页面，而不是本地管理端口。

### 2.3 安全边界

- 消息只负责唤醒和跳转；
- 消息链接不携带可直接建立管理会话的长期凭证；
- 链接被转发后不能绕过登录、TOTP 和设备授权；
- 高风险操作必须在 WebUI 内重新 step-up；
- 不在 IM 内直接完成批准或取消。

## 3. WebUI 独立上云的推荐拓扑

```text
Internet
  -> TLS 终止/反向代理（可信、明确配置）
  -> 云端 WebUI/控制面（仅内网监听或受保护端口）
  -> MySQL（不暴露公网）
  -> 出站通知（飞书/钉钉）
```

要求：

- 全链路 HTTPS；
- 反向代理只信任明确配置的来源；
- 严格校验 Host 和 Origin；
- Secure、HttpOnly、SameSite Cookie；
- 服务端统一认证、授权和 CSRF；
- 前端不保存密钥；
- 管理端口不直接暴露公网；
- 远程模式配置不完整时拒绝启动；
- 数据库只允许受控网络访问；
- 备份加密并验证恢复。

## 4. 反向代理的职责

反向代理不是“为了飞书/钉钉”而存在，而是为了：

- TLS 终止；
- 隐藏应用端口；
- 请求大小和超时限制；
- 可信的 `X-Forwarded-*` 头；
- 访问日志与限流；
- 统一安全响应头。

代理配置必须与应用配置一致；应用不能无条件信任任意代理头。

## 5. 决策：是否使用 Tailscale

| 场景                   | 是否需要 Tailscale       | 建议                               |
| ---------------------- | ------------------------ | ---------------------------------- |
| 飞书/钉钉仅出站通知    | 否                       | 直接使用 HTTPS Webhook             |
| 单人远程访问云端 WebUI | 否                       | 公网 HTTPS + 强认证                |
| 不希望公开管理面       | 可选                     | Tailscale/WireGuard + 仍然启用认证 |
| 本地管理面临时远程访问 | 可选但不推荐作为产品方案 | 优先使用云端控制面                 |

## 6. 启动门禁

远程模式必须显式配置，至少校验：

- `deploymentMode=remote`；
- HTTPS 终止已配置；
- `secureCookie=true`；
- 允许的 Host 列表非空；
- 允许的 Origin 列表非空；
- 可信代理配置明确；
- 管理监听地址不是无保护的公网绑定，或由受控代理隔离。

任一项不满足时必须拒绝启动，不能仅打印警告后继续。
