## 2. 设计

- 新增 `src/codex/control/delivery-assurance.js`；
- 冻结清单和交付包写入不可变本地 assurance store；
- 验证只能使用服务端注入 runner，AI/provider 提供的 signer 或 runner 被忽略/拒绝；
- 冻结测试在验证运行前后重新哈希，任一变化即失败；
- 跳过、未运行、取消和超时不能被折叠成 passed；
- 交付包必须显式列出未执行检查、回滚说明、artifact/commit 和证据引用；
- 再交付必须引用已接受父包、使用新 artifactHash 并声明受影响 AC，历史包不覆盖。

## 3. 安全边界

- 测试文件路径限制在项目内，拒绝 traversal、symlink、binary 和超限文件；
- 不持久化原始日志、CoT、密钥、绝对路径或完整 diff；
- 同一证据 ID 不得重放，同一 package ID 不得重新写入；
- 验证证据内容被修改后不能用于打包；
- AI 只能提供候选修复，不能给最终交付签字。
