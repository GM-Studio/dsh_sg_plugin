# 回滚、停用与恢复手册

- 日期：2026-10-23
- 分支：`feat_web`
- 状态：**设计基线；演练证据尚未产生**
- 目标：在不伪造审计、不静默丢失决策的前提下，快速停用远程能力并恢复到已知安全状态。

## 1. 回滚原则

1. 先阻断新的高风险操作，再处理在途任务；
2. 先保留证据，再删除或重建运行资源；
3. 不把“服务已停止”误写成“决策已撤销”；
4. 不静默覆盖旧 Decision、旧 artifactHash 或审计记录；
5. 任何恢复动作都要有可复核的命令、时间、操作者和结果；
6. 未演练的恢复步骤不得标记为可用。

## 2. 停用层级

| 层级           | 动作                                       | 预期效果                   | 风险                         |
| -------------- | ------------------------------------------ | -------------------------- | ---------------------------- |
| L1 通知停用    | 禁用飞书/钉钉渠道，保留 Attention 生命周期 | 停止外部寻呼，不停止控制面 | 人可能错过到期               |
| L2 决策停用    | 进入只读模式，拒绝新 Decision 与高风险操作 | 保留查看和审计             | 在途 Worker 可能继续运行     |
| L3 Worker 撤销 | 撤销 Worker 令牌和项目白名单               | 阻止新的领取与应用         | 已领取任务需要超时或人工回收 |
| L4 WebUI 下线  | 停止公网入口或反向代理                     | 阻断远程访问               | 不能证明数据库安全           |
| L5 控制面停用  | 停止应用并进入维护模式                     | 冻结写入                   | 未完成事件可能丢失，需先核对 |
| L6 数据恢复    | 从加密备份恢复到隔离实例                   | 恢复已知时间点             | 可能丢失备份点之后的数据     |

推荐顺序：L1/L2 -> 核对在途任务 -> L3 -> L4 -> L5 -> 必要时 L6。

## 3. 云端 WebUI 停用

### 3.1 步骤

1. 将部署切到只读或维护模式；
2. 关闭新会话创建和高风险 mutation；
3. 记录当前时间、部署版本、配置版本和数据库备份点；
4. 停止反向代理到应用的流量；
5. 停止应用进程；
6. 保留数据库、审计、通知投递和备份；
7. 撤销所有活动会话和设备；
8. 输出停用报告并关联审计记录。

### 3.2 验证

- 公网入口不可达；
- 旧 Cookie 不能继续访问；
- 应用没有新的写入；
- 数据库仍可只读核对；
- 停用动作本身已审计。

### 3.3 禁止事项

- 不通过删除数据库表来“快速停用”；
- 不在未备份时重建数据库；
- 不把关闭通知渠道当作关闭控制面；
- 不删除仍处于 `PENDING_APPLY` 的 Decision。

## 4. Worker 撤销

1. 将 Worker 标记为撤销，停止发放新租约；
2. 立即吊销独立 Worker 令牌；
3. 从项目白名单移除该 Worker；
4. 等待或强制释放租约；
5. 将已领取但未完成的 Run 标记为 `BLOCKED` 或等价状态，不伪造完成；
6. 撤销本地会话和临时凭证；
7. 审计撤销原因和操作者。

验证要求：

- 撤销后的令牌不能领取任务；
- 不能读取未授权项目；
- 不能应用旧 Decision；
- 已执行中的本地进程有明确处置记录；
- 重新启用必须使用新令牌并重新审批。

## 5. MySQL 备份与恢复

### 5.1 备份

- 使用一致性快照或受控逻辑备份；
- 备份包含 schema 版本、迁移记录和审计链；
- 备份加密，密钥与备份分离保存；
- 记录备份开始/结束时间、校验和、大小和保留期；
- 备份不得包含未脱敏源码、原始日志或明文凭证。

### 5.2 恢复

1. 在隔离实例恢复，不直接覆盖生产库；
2. 校验 schema 版本和迁移完整性；
3. 校验审计链和关键唯一约束；
4. 抽查 Decision 幂等键、artifactHash、WorkItem 版本；
5. 核对 `PENDING_APPLY`、未完成 Run 和 Attention；
6. 由人工确认数据时间点和业务影响；
7. 切换流量并记录恢复审计。

### 5.3 验收证据

- 备份命令与退出码；
- 备份校验和；
- 恢复命令与退出码；
- 恢复后行数、约束和审计校验结果；
- 恢复耗时与数据丢失窗口；
- 操作者和审批记录。

未完成真实恢复演练时，状态必须为 `NOT_RUN`。

## 6. 通知渠道禁用与密钥轮换

### 6.1 禁用

- 关闭飞书/钉钉渠道开关；
- 停止 outbox 投递，不删除待处理 Attention；
- 记录未投递项和最后错误；
- 保留独立投递记录；
- 通过站内收件箱或其他已批准渠道告知 owner。

### 6.2 Webhook 与密钥轮换

1. 在平台创建新 Webhook 或新凭证；
2. 更新服务端密钥引用，不写入前端或日志；
3. 验证新凭证可投递测试消息；
4. 撤销旧凭证；
5. 对失败投递执行受控重试；
6. 审计轮换时间和操作者，不记录密钥值。

密钥泄露时：

- 立即禁用旧渠道；
- 撤销旧凭证；
- 检查投递记录和异常访问；
- 评估通知内容暴露；
- 重新审批后恢复。

## 7. 旧 Decision 与旧 artifact 失效

- artifactHash 变化后，旧 Decision 标记 `STALE`；
- Worker 应用前必须重新校验 hash 和 WorkItem 版本；
- 旧 Decision 不删除，保留审计关联；
- 生成新的 Attention，要求重新决策；
- 旧通知链接只能显示失效或重新进入登录流程；
- 不自动把旧批准迁移到新制品；
- 历史 Delivery 保留，新 Delivery 引用原 Delivery 和受影响 AC。

## 8. 审计与保留期

- 停用、撤销、恢复、删除和密钥轮换都必须写入审计；
- 执行事件默认保留 7 天；
- 通知投递默认保留 30 天；
- Decision 与 Audit 默认保留 1 年；
- 删除必须留下删除审计；
- 审计链损坏时显式失败或告警，不静默跳过；
- 备份和导出按高敏感数据管理。

## 9. 演练矩阵

| 演练              | 最低证据                         | 当前状态 |
| ----------------- | -------------------------------- | -------- |
| 关闭远程 WebUI    | 入口不可达、旧会话失效、停用审计 | NOT_RUN  |
| 撤销 Worker       | 令牌失效、租约释放、越权拒绝     | NOT_RUN  |
| 飞书失败/钉钉成功 | 独立投递、重试上限、无重复轰炸   | NOT_RUN  |
| Webhook 轮换      | 新凭证成功、旧凭证失败、审计     | NOT_RUN  |
| MySQL 备份恢复    | 校验和、恢复结果、数据丢失窗口   | NOT_RUN  |
| 审计链损坏        | 显式失败或告警                   | NOT_RUN  |
| 旧 artifact 变化  | 旧 Decision STALE、新 Attention  | NOT_RUN  |

## 10. 退出条件

回滚方案只有在以下条件满足后才算可用：

- 每项停用动作有明确负责人和审批方式；
- 每项恢复动作在隔离环境演练并留证；
- 数据库备份可恢复且审计链可校验；
- 通知渠道可独立禁用和轮换；
- Worker 可撤销且不能继续应用旧决策；
- 演练失败项被记录并重新演练；
- 未执行项保持 `NOT_RUN`，不得以设计完成代替演练。
