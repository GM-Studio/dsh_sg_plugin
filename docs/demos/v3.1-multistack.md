# SpecGate v3.1 多技术栈使用说明

> 对应 `V3.1-REQ-001`。v3.0 的单套件项目不需要任何改动。

## 1. 配置套件

```yaml
# .specgate/config.yaml
workflowVersion: 3
stack: web                 # node | node-fullstack | web | python
changeKey: checkout-2026-10
install: true              # 全局默认；false 关闭安装
suites:
  - id: web-unit
    kind: node-test
    command: ["pnpm", "test:json"]
    cwd: "."
  - id: web-e2e
    kind: command
    command: ["pnpm", "test:e2e"]
    cwd: "."
    timeoutMinutes: 40
  - id: api
    kind: pytest
    cwd: "server"
    pytestArgs: ["-q", "tests"]
    python: "3.12"
```

- `kind: node-test` / `command`：项目命令负责写 `SG_REPORT`（v3.0 的 test:json 契约）。
- `kind: pytest`：插件用项目 `.venv` 执行 `python -m pytest --junitxml=…`，按用例名里的 `[AC-xxx]` 映射。
- 没有 `suites` 时退化为单套件 `default`，沿用 `testing.command` / `scripts["test:json"]`。

## 2. AC 归属

```json
{
  "requirements": [
    { "ac": "AC-001", "covers": ["REQ-001"], "tasks": ["T-001"], "cases": ["TC-001"], "suite": "web-unit" },
    { "ac": "AC-004", "covers": ["REQ-002"], "tasks": ["T-002"], "cases": ["TC-004"], "suite": "api" }
  ]
}
```

多套件时 `suite` 必填；每个 AC 只能属于一个套件。

## 3. 版本与环境

| 项 | 行为 |
|---|---|
| Node 18–24 | 读 `.nvmrc` / `.node-version` / `engines.node`；探测 volta / fnm / nvm-windows / asdf；只改子进程 PATH；切换后 `node -v` 校验 |
| Python 3.9–3.13 | 读 `.python-version` / `requires-python`；有 `.venv` 复用，版本不符失败且不删除；不存在则创建 |
| 依赖安装 | `install: true` 且存在 lockfile 时执行；`install: false` 关闭；无 lockfile 默认跳过 |
| 包管理器 | Node：npm / pnpm / yarn / bun；Python：pip / uv（poetry.lock 存在时回退 pip） |

## 4. 跨仓 changeKey

```bash
/sg-change add-checkout --type feature --link checkout-2026-10
```

- 每个仓各自 H1/H2/H3、各自 tag、各自归档；
- `changeKey` 出现在 status、验收报告与证据里，只用于追溯；
- 不做跨仓锁，也不做跨仓汇总验收。

## 5. 各类仓库示例

### Node 后端

```yaml
stack: node
suites:
  - id: api
    kind: node-test
    command: ["npm", "run", "test:json"]
```

### Vue / React 前端

```yaml
stack: web
suites:
  - id: web-unit
    kind: node-test
    command: ["pnpm", "test:json"]
  - id: web-e2e
    kind: command
    command: ["pnpm", "test:e2e"]
```

E2E 的后端/DB/浏览器由 `test:e2e` 自行准备；插件不装浏览器、不起 Docker。

### Python 后端

```yaml
stack: python
suites:
  - id: api
    kind: pytest
    cwd: "."
    pytestArgs: ["-q", "tests"]
    python: "3.12"
```

pytest 需要存在于 `.venv`：把 `pytest` 写进 `requirements.txt` 或 `pyproject.toml`，安装阶段会一并装好。

## 6. status 运行时

每次执行套件后，`/sg-status` 会显示该套件最近一次的运行时来源：

```text
套件：web-unit, api
运行时 api：Node 18.19.0（nvm），安装 skipped:no-lockfile，上次 pass(0)
运行时 web-e2e：Python 3.12.10（.venv），安装 done，上次 pass(0)
```

- Node：版本、来源工具（volta/fnm/nvm/asdf）、切换目录。
- Python：版本、`.venv` 路径、是否新建/复用。
- 安装：`done` / `skipped` / `reused` 及原因。
- 上次运行：pass/fail 与 exitCode。

运行时记录写入 `.specgate/state.json` 的 `runtime.suites`，不进入证据哈希链。

## 7. Agent 池

`sg_run` 派发 implementer / tester 时按「仓库 + 角色」复用 agent，reviewer 每次新建以保持独立。

```yaml
pool:
  enabled: true          # false 退回每次新建
  poolSize: 2            # 每角色最多 2 个
  maxLeasedPerChange: 6  # 单 change 并发租用上限（含 reviewer）
  reuseTasks: 3          # 连续 3 个任务后销毁重建
  contextThreshold: 0.7  # 上下文达到 70% 也重建
  contextTokens: 128000
  ttlMinutes: 10         # 空闲 10 分钟回收
  breakerFailures: 2     # 同一角色连续失败 2 次熔断
```

- 复用任务之间注入上一任务摘要（task/AC/结果），不保留完整对话；DSH 没有清空会话的 API，因此用“有界历史”控制令牌增长。
- 复用时通过 `working_directory` 切到当前任务的 worktree。
- change 归档只销毁该 change 用过且空闲的 agent；abort 保留。
- `/sg-status` 显示创建/复用/销毁/回收/失败与各角色池大小。

## 8. 当前边界

- 不支持 conda / pdm；
- 不保证 Node 18 以下、Python 3.9 以下；
- 不内置 Docker 编排；
- 多套件默认串行执行；
- `poetry.lock` 目前回退到 `pip install -e .`。
