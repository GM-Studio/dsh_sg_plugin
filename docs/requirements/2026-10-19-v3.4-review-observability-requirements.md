# SpecGate v3.4 需求：状态路径、真审查、真格式化与全链路可观测

- 文档 ID：V3.4-REQ-001
- 状态：Draft，待审查
- 日期：2026-10-19
- 基线：v3.3.1

## 1. 背景

当前 v3 存在四个缺口：

1. `/sg-status` 只能看当前目录，不能指定其他仓库。
2. reviewer 只拿到摘要/片段，不是真实 diff；blocking 没有强制 file/line/证据；没有独立 review worktree；集成阶段没有全量审查。
3. v3 没有 formatter 阶段，代码格式不进入门禁。
4. 角色执行结果没有统一的运行记录，`/sg-status` 无法展示时间线与可追踪信息。

本需求把四件事一起闭环：**指定路径查看、真审查、真格式化、全链路可观测**。

## 2. 功能需求

### FR-1 `/sg-status --path`

- 语法：`/sg-status [--path <dir>] [--json] [--verbose]`。
- `--path` 指向**仓库根**，直接读取 `<dir>/.specgate/state.json`；不做向上查找。
- 不带 `--path` 时使用当前工作目录。
- 支持 Windows（`E:\repo`、`E:/repo`）与 POSIX（`/repo`）路径形式；相对路径按当前目录解析。
- `--json` 输出结构化对象；默认输出人读文本。
- `--verbose` 追加运行时间线（来自 FR-4 的 runs）。
- 路径不存在、没有 `.specgate/state.json`、state 非法时返回明确错误码：`PATH_NOT_FOUND`、`STATE_MISSING`、`STATE_INVALID`。
- 只读：不得写 state、锁、工作树或 runs。

### FR-2 真审查

#### 2.1 reviewer prompt 带真实 diff

- 任务审查：`git diff <task.base>..<task.head>`。
- 集成审查：`git diff <base>..<integration HEAD>`。
- prompt 中放入完整 diff；单次上限 **200KB**，超出时截断并附：
  - 完整文件清单与每个文件 +/− 行数；
  - 被截断的文件名与字节数；
  - 明确标注 `diff 已截断，但审查范围仍是全部文件`。
- diff 中疑似密钥行替换为 `[REDACTED]`。

#### 2.2 独立 review worktree

- 每次审查用 `git worktree add --detach <reviewedCommit>` 创建临时 worktree；审查结束（成功或失败）删除。
- reviewer 在该 worktree 内：
  - 读取 diff；
  - 跑该任务的 suite（任务审查）或全部 suite（集成审查）；
  - 禁止写任何文件（role diff/guard 拒绝写操作）。
- 测试失败直接作为 blocking，不需要 reviewer 自由发挥。

#### 2.3 blocking 证据格式

- reviewer 必须输出 JSON：
  ```json
  {
    "verdict": "pass|fail",
    "blocking": [
      {
        "file": "src/a.js",
        "line": 42,
        "severity": "high|medium",
        "evidence": "diff 片段或测试输出",
        "reason": "为什么这是问题"
      }
    ],
    "nonBlocking": []
  }
  ```
- 校验规则（任一不满足则整份 reviewer 输出判无效）：
  - `file` 必须出现在本次 diff 的文件清单中；
  - `line` 必须是正整数，且落在该文件的 diff hunk 行号范围内；
  - `evidence` 非空，且能在 diff 或测试输出中找到对应片段（允许去除空白后匹配）；
  - `verdict=fail` 必须至少一条 blocking；`verdict=pass` 必须 blocking 为空。
- 校验通过后，blocking 数量与内容写入证据链。

#### 2.4 集成全量审查

- INTEGRATING 在回归通过后、生成验收报告前，执行一次全量审查：
  - diff 为 `base..integration HEAD`；
  - reviewer 在独立 review worktree 中跑全部 suite；
  - 任何 blocking 阻断 H3，并把问题写回任务/证据。
- 集成审查报告写入 `openspec/changes/<change>/reviews/integration.json`。

### FR-3 真格式化

- 新增 formatter 阶段，位置：**implementer 之后、tester 之前**。
- 命令来源：`.specgate/config.yaml` 的 `formatter.command`（argv 数组）。
- 未配置时：跳过，写 `format-report.md` 标记 `not-configured`，不阻断。
- 配置时：
  - 独立 formatter agent 在独立 worktree 中运行命令；
  - 允许修改源码并提交格式化提交；
  - 生成 `openspec/changes/<change>/reviews/format-report.md`，含命令、退出码、改动文件、耗时；
  - 退出码非 0、或命令后仍有未提交的格式改动、或 format-report 缺失 → 任务失败。
- formatter 不得修改 tests 或 change 包；diffCheck 对 formatter 角色单独约束。

### FR-4 全链路可观测

- `state.runs` 记录每次角色调用：
  ```json
  {
    "change": "x",
    "task": "T-001",
    "role": "implementer|tester|formatter|reviewer",
    "agentId": "…",
    "worktree": "…",
    "commit": "…",
    "commands": ["…"],
    "durationMs": 1234,
    "result": "pass|fail",
    "error": null
  }
  ```
- 运行记录追加到 `.specgate/runs/<change>.jsonl`（gitignore），同时保留在 `state.runs` 最近 200 条。
- `/sg-status --verbose` 展示最近 20 条时间线：时间、角色、任务、结果、commit 短码、耗时。
- `/sg-status --json` 输出 `runs` 与 `reviews` 摘要。
- 证据链额外记录 reviewer/formatter 的 agent id、worktree、commit、报告 hash。

## 3. 非功能需求

- **路径安全**：`--path` 只读；拒绝 `..` 逃逸到非仓库目录；不跟随符号链接写到仓库外。
- **diff 上限**：200KB；不因超大 diff 阻塞流程，但必须给出截断说明。
- **确定性**：同一 commit/diff 生成相同 prompt 与报告（时间戳除外）。
- **离线**：除模型调用外不联网。
- **脱敏**：diff、报告、runs 中疑似密钥替换为 `[REDACTED]`。
- **幂等**：review worktree 用完即删；重复执行不残留。
- **可维护**：review/formatter 校验逻辑独立模块，可单测。
- **性能**：status 读取 <2 秒；review worktree 创建/删除 <5 秒（不含测试）。

## 4. 验收标准

- AC-1：`/sg-status --path E:\repo` 与 `/sg-status --path /repo` 都能读到目标仓库状态；不带参数用当前目录。
- AC-2：`--json` 输出可解析对象，含 phase/change/tasks/runs/reviews；`--verbose` 显示时间线。
- AC-3：reviewer prompt 包含真实 diff；超过 200KB 时有截断说明与完整文件清单。
- AC-4：blocking 缺 file/line/evidence 或 line 不在 diff 中时，reviewer 输出判无效并阻断。
- AC-5：任务审查与集成审查都使用临时 review worktree，审查后删除；测试失败直接 blocking。
- AC-6：INTEGRATING 全量审查 blocking 时不能进入 H3。
- AC-7：formatter 在 implementer 后 tester 前执行；未配置跳过并记录；失败阻断任务。
- AC-8：`state.runs` 与 `.specgate/runs/<change>.jsonl` 记录角色/agent/worktree/commit/耗时/结果；status 可查看。
- AC-9：单测覆盖路径解析、diff 截断、blocking 校验、formatter 阻断、runs 记录；`node --test` 全绿。

## 5. 实施切片

1. status `--path/--json/--verbose` 与路径解析。
2. runs 记录与 JSONL、status 时间线。
3. review 模块：diff 收集、200KB 截断、review worktree、blocking 校验。
4. executor 接入任务 review；INTEGRATING 接入全量 review。
5. formatter 阶段、配置、报告与阻断。
6. 测试与文档。

## 6. 明确不做

- 不做 reviewer 模型切换/多模型投票。
- 不做 formatter 自动探测命令（只读配置）。
- 不做 review worktree 跨任务复用（用完即删）。
- 不做 runs 的 Web UI，只做文本/JSON。
