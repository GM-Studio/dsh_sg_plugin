# SpecGate v3.9 需求：初始化即生成「MVP 框架搭建」第一变更

- 文档 ID：V3.9-REQ-001
- 状态：已确认（2026-10-19）
- 基线：v3.8.0
- 决策来源：2026-10-19 对话第 1–9 轮问答
- 实现版本：3.9.0

## 1. 背景

v3.8 的 `sg-init` 确认后只生成最小脚手架与示例 change `add-version`（实现 `/version`），与用户真实需求无关，也没有可复用的 CRUD 样板。新需求要求：初始化完成时，第一变更就是 **MVP 框架搭建**，并带一个可执行的 Item CRUD 示例与功能描述。

## 2. 决策记录

| # | 决策 | 选择 |
|---|---|---|
| 1 | CRUD 示例对象 | 通用 Item（id/name/description） |
| 2 | 代码生成时机 | init 只生成 change 包；代码由 `/sg-run` 执行任务生成 |
| 3 | 第一变更名称 | `mvp-scaffold`，proposal 标题「MVP框架搭建」 |
| 4 | 技术栈范围 | java / node / python |
| 5 | 非功能要求 | 全接口测试覆盖；不引入数据库/外部服务；格式/静态检查通过 |

| 8 | 栈范围细化 | java / node / python；不含 monorepo/前端/generic |
| 9 | 功能描述位置 | change 的 proposal + specs delta，不额外生成 docs 文件 |

## 3. 功能需求

### FR-1 框架需求注入

- 仅新项目（`mode=new`）且栈为 java/node/python 时，需求文档第一条固定为：
  `FR-001 MVP 框架与 Item CRUD 示例（框架基线）`。
- 业务功能需求顺延为 `FR-002+`；`openspec/REQ.md` 对应 `REQ-001` 与 `REQ-002+`。
- `FR-001` 的验收标准：`启动项目后 Item CRUD 全接口测试通过（GET/POST/PUT/DELETE + 404/400）`。
- `FR-001` 不接受删除；「修改需求」或切换技术栈后自动补齐/移除。
- 非后端栈与既有项目不注入。

### FR-2 第一变更 mvp-scaffold

- 新后端项目确认后，首个 change 为 `mvp-scaffold`，proposal 标题「MVP框架搭建」。
- 变更引用 `REQ-001`；后续业务 change 引用 `REQ-002+`。
- 其他栈继续使用 `add-version`。

### FR-3 Item CRUD 契约

| 方法 | 路径 | 成功 | 失败 |
|---|---|---|---|
| GET | `/api/items` | 200 数组 | — |
| GET | `/api/items/{id}` | 200 | 404 |
| POST | `/api/items` | 201 | 400（name 为空） |
| PUT | `/api/items/{id}` | 200 | 404 / 400 |
| DELETE | `/api/items/{id}` | 204 | 404 |

- 内存存储；不引入数据库/消息队列/外部服务。
- 测试覆盖 5 个接口成功路径 + 404 + 400。

### FR-4 Change 包内容

`openspec/changes/mvp-scaffold/` 必须包含：

- `proposal.md`：问题/目标/非目标/影响面，标题「MVP框架搭建」，引用 `REQ-001`。
- `specs/mvp/spec.md`：`### Requirement: MVP 框架与 Item CRUD 示例 (REQ-001)` + 10 个 Scenario（AC-001..AC-010）。
- `design.md`：目标与非目标 / 任务图 / AC 到用例 / 风险。
- `tasks.md`：T-001..T-003。
- `tests/cases.md`：TC-001..TC-010。
- `tests/mapping.json`：10 条 AC 映射到 REQ-001、任务、用例与 suite。
- `tests/touched.json`：bootstrap/modify 文件清单。

### FR-5 任务拆分

- **T-001** Item 模型 + 内存存储 + 列表/详情（AC-001..AC-003）。
- **T-002** 创建/更新/删除 + 校验（AC-004..AC-009），depends T-001。
- **T-003** 全接口测试 + 格式/静态检查（AC-010），depends T-001/T-002。

### FR-6 栈适配

| 栈 | 实现文件（任务生成） | 测试 |
|---|---|---|
| java | `Item.java`、`ItemStore.java`、`ItemController.java` | `ItemControllerTest.java`（MockMvc） |
| node | `src/items.js` + `index.js` | `test/items.test.mjs`（node:test） |
| python | `app/items.py` + `app.py` | `tests/test_items.py`（pytest） |

- suite：java `backend`；node/python `api`。
- 前端 / monorepo / generic 不生成 `mvp-scaffold`。

### FR-7 初始化结果

- 状态 `H1_PENDING`，`change = mvp-scaffold`。
- 结果摘要显示脚手架文件、`mvp-scaffold`、「MVP框架搭建」、下一步 `/sg-run`。
- 结果通过 `agent.followup` 进入对话历史。

### FR-8 既有项目与兼容

- 既有项目（`mode=existing`）不注入框架需求、不生成 `mvp-scaffold`。
- 现有 `java_demo` 不迁移。
- H1/H2/H3 门控语义不变。
