# SpecGate v3.10 需求：init 自动生成 CRUD 代码并跑质量流水线

- 文档 ID：V3.10-REQ-001
- 状态：已确认（2026-10-19）
- 基线：v3.9.0
- 实现版本：3.10.0

## 1. 背景

v3.9 的 init 只生成 `mvp-scaffold` change 包，CRUD 代码要等 `/sg-run` 执行任务。用户要求初始化后直接得到可运行的 Item CRUD 代码与测试，并自动跑格式化、静态检查、测试与审查；成功后自动归档第一变更。

## 2. 决策记录

| # | 决策 | 选择 |
|---|---|---|
| 1 | 收尾方式 | 自动完成并归档 `mvp-scaffold`，项目回到 `IDLE` |
| 2 | 审查范围 | 格式化修复 + 静态检查 + 测试 + reviewer 子 Agent |
| 3 | 失败处理 | 中止并保留报告，停在 `H1_PENDING` |
| 4 | 技术栈 | java / node / python |

## 3. 功能需求

### FR-1 代码生成

新后端项目确认后，在 `mvp-scaffold` 创建后生成：

- **java**：`Item.java`、`ItemStore.java`、`ItemController.java`、`ItemControllerTest.java`。
- **node**：`src/items.js`、重写 `index.js`、`test/items.test.mjs`。
- **python**：`items.py`、重写 `app.py`、`tests/test_items.py`。

### FR-2 CRUD 契约

GET/POST/PUT/DELETE `/api/items`（含 `/{id}`），内存存储；201/204/400/404 全覆盖；5 个接口的成功与边界用例。

### FR-3 质量流水线

- **格式化**：Java `mvnw spotless:apply`；Node 若配置 `scripts.format` 则执行；Python 暂不强制。
- **静态检查**：Java `mvnw checkstyle:check`；Node 若配置 `scripts.lint` 则执行。
- **测试**：Java `mvnw verify`；Node `node --test test/items.test.mjs`；Python `python -m pytest -q tests`。
- **审查**：`reviewer` 子 Agent 只读审查新增文件，返回 `{verdict, blocking}`；`fail` 即中止。

### FR-4 成功归档

- 任务标记 `[x]`。
- 规格 delta 应用到 `openspec/specs/mvp/spec.md`。
- `mvp-scaffold` 移入 `openspec/changes/archive/<date>-mvp-scaffold`。
- 状态回到 `IDLE`、`change=null`，git 提交。
- 写 `docs/mvp-scaffold-report.md`（生成文件、各阶段命令/退出码/耗时、审查结果）。

### FR-5 失败处理

- 任一阶段非 0 → 停在 `H1_PENDING`，`change=mvp-scaffold`。
- 保留代码与 `docs/mvp-scaffold-report.md`。
- 写 `openspec/changes/mvp-scaffold/reviews/bootstrap-failure.md`。
- 不归档、不勾选任务。

### FR-6 无审查能力时

- 宿主没有 `subagents` 服务时，`maybeBuildBootstrap` 跳过自动构建，保留 `H1_PENDING`，由 `/sg-run` 继续；避免静默跳过审查。

### FR-7 兼容

- 仅新项目 java/node/python；前端/monorepo/generic 与既有项目不变。
- `java_demo` 不迁移。

## 4. 非功能需求

| 编号 | 要求 |
|---|---|
| NFR-1 可运行 | 生成的代码与测试在对应工具链下可直接运行 |
| NFR-2 可追溯 | 报告记录每条命令、退出码、耗时与审查结论 |
| NFR-3 零写边界 | 确认前零写；自动构建只发生在确认后 |
| NFR-4 幂等 | 已归档后重复 init 幂等跳过 |
| NFR-5 兼容 | 不改变既有 H1/H2/H3 语义与前端栈行为 |

## 5. 验收标准

- **AC-1** Java 新项目 init 后生成 4 个 Item 文件，状态 `IDLE`，`mvp-scaffold` 已归档。
- **AC-2** Node/Python 生成对应代码与测试文件。
- **AC-3** 质量失败时停在 `H1_PENDING`，报告与失败文件存在，任务未勾选。
- **AC-4** 无 subagents 时 `maybeBuildBootstrap` 跳过，状态保持 `H1_PENDING`。
- **AC-5** 归档后 `openspec/specs/mvp/spec.md` 存在，`openspec/changes/mvp-scaffold` 不再存在。
- **AC-6** 全量 `node --test` 全绿。

## 6. 实现结果（2026-10-19）

- 新增 `src/v3/bootstrap-code.js`（三栈代码模板）与 `src/v3/bootstrap.js`（质量/审查/归档流水线）。
- `commands.js` / `tools.js` 在 init 返回后调用 `maybeBuildBootstrap`。
- 新增 `test/v3/s40.bootstrap.test.js`（5 项）。
- 全量 `node --test`：**301 tests，297 pass，0 fail，4 skipped**。

### 已知边界

- Java/Python 需要本机有 Maven/JDK/pytest；工具链缺失会按失败处理并保留报告。
- reviewer 依赖 `subagents`；不可用时跳过自动构建。
- 内存存储不持久化，仅用于框架演示。
