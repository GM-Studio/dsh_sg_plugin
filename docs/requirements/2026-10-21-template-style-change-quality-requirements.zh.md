## 1. 目标与问题

将 Golden 模板、sg-init 生成工程、前后端 CRUD 示例建立为同一套可运行、可检查、可复用的标准样例。sg-change 新增功能、API 和页面时应读取项目内的样例与规范，并通过实际执行的质量检查证明实现符合要求。

验收必须区分“模板曾通过验收”“本次只生成文件”“当前项目实际验证通过”。日志、测试报告、覆盖率和代码走查结果要能与对应的源码版本对账，不能根据生成成功、提示语或模板哈希推断测试成功。

## 3. 范围与现有行为

### 3.1 范围

- Java 配置：JDK 8 / Spring Boot 2.7、JDK 17 / Spring Boot 3.5、JDK 21 / Spring Boot 3.5、JDK 21 / Spring Boot 4.0 preview。以现有版本清单为基础，依赖精确版本及兼容性在实现前核实。
- 前端：沿用 Vue 3、TypeScript、Vite、Element Plus 的最小管理界面，提供真实可操作的功能样例。
- 工作流：sg-init 的模板与报告、sg-verify 的执行与对账、sg-change 的样例引用、实现、检查、走查和完成门禁。
- 文档与工具：代码风格约定、API 文档、测试示例、质量脚本、Golden 记录及验收证据。

### 3.2 不扩大本轮范围

- 不同时重构历史 Node.js、Python、React 模板；保留既有 GET/POST JSON 约定并运行相关回归，防止被本轮改动破坏。
- 不建设完整权限管理平台、动态菜单管理、组织架构、注册/找回密码、SSO、多租户。
- 不增加 Excel、对象存储、异步大文件导入导出、分布式 Session、生产部署设施。
- 不自动覆盖或迁移已经生成、且可能经过用户修改的业务工程。

### 3.3 现有事实与衔接

- 当前默认 Java 示例已有基础 CRUD 和基础全局异常处理。本轮进行规范化与扩展，不另建一套平行模板。
- 当前 API 约定直接返回实体/数组，并未统一包装。本轮拟改为统一响应对象，属于新生成模板的契约变更，需同步前端、测试、文档、运行验证器和 Golden。
- 当前已有覆盖率分析能力不等于默认 Java/Vue 模板已强制满足覆盖率要求；本轮必须实际接通报告生成、阈值判断和失败门禁。
- 旧 v4.3 需求中的“不做鉴权、分页”等限制，在本轮批准的模板范围内由本文替代；其他未冲突的目标保护、离线生成和真实证据要求继续保留。

## 4. 功能需求

### FR-01 单一模板来源与可追踪样例

1. Golden 与 sg-init 使用同一套可读模板来源；示例代码能独立打开、审阅和测试，避免靠多个字符串副本手工同步。
2. 生成工程内同时提供后端、前端 API、页面、单元测试、接口测试和规范文档作为参考样例。
3. 记录模板/规范版本、样例相对路径及内容摘要；不得把开发者本机绝对路径作为后续复用前提。
4. 源码变化使旧验证记录失效。只有对新内容实际验收后才能更新有效 Golden 记录。

### FR-02 Java 与前端代码风格

1. Java 以阿里巴巴 Java 开发规范为基准，明确适用版本、规则映射及允许的例外。
2. 后端示例采用 Controller、Service、Repository、Entity、请求 DTO、响应 VO 的职责划分；Controller 不直接承载持久化和核心业务逻辑，不直接向外暴露持久化实体。
3. 统一命名、包结构、构造器依赖注入、校验位置、异常与错误码、事务边界、日志及注释方式；复杂逻辑不得仅为分层而复制。
4. Java 格式化器、Checkstyle、PMD 等工具的具体组合须兼容四套配置，形成唯一可重复执行的配置；不能把某一个工具通过宣称为全部阿里巴巴规范符合。
5. Vue/TypeScript 建立适合前端的对应规范：独立类型化 API 模块、公共请求封装、统一错误处理、页面与组件职责划分，统一命名和 ESLint/Prettier 配置。Java 手册不直接作为前端规则集。
6. 样例同时演示正确与失败路径；风格规则有对应的机械检查或明确的走查项。

### FR-03 HTTP、统一响应与异常

1. 查询 GET，其他业务操作 POST；GET 不携带 body，修改/删除等操作的 id 放在 JSON body。
2. 普通响应使用 `ApiResponse<T>`，建议字段为 `code`、`message`、`data`、`traceId`；成功 `code=0`，失败为稳定的业务错误码。HTTP 状态表达成功、校验失败、未登录、无权限、资源不存在等语义，不把所有错误都包装成 HTTP 200。
3. 分页 `data` 包含 `records`、`total`、`page`、`pageSize`，不直接泄漏框架分页类型。
4. 全局异常覆盖参数校验、非法 JSON、业务异常、资源不存在、方法/媒体类型不支持、认证/授权失败、文件和导入失败、未预期异常。过滤器/安全链错误也须使用约定的 JSON 响应。
5. 响应不包含堆栈、数据库细节、文件绝对路径和凭证；内部错误日志通过 traceId 关联，密码、Cookie、Session 标识不得进入日志。
6. 成功状态保持明确：新增可用 201，其余有响应体的成功操作用 200；删除返回 JSON 回执。
7. 文件例外仅限上传请求、成功的下载/导出响应；上传回执、文件元数据及文件操作的错误仍为统一 JSON。例外在 API 文档中逐项说明。

### FR-04 Task CRUD、分页与批量操作

沿用 Task 作为完整业务样例，包含创建、修改、详情、删除、分页列表、批量删除和批量完成状态更新。

| 用途 | 方法与路径建议 | 参数及结果要求 |
| --- | --- | --- |
| 分页查询 | GET `/api/tasks` | query：page、pageSize、title、completed、sortBy、sortOrder；返回分页对象 |
| 详情 | GET `/api/tasks/{id}` | 返回 Task VO；不存在返回 404 |
| 新增 | POST `/api/tasks` | JSON title、completed；返回新记录 |
| 修改 | POST `/api/tasks/update` | JSON id、title、completed；返回更新记录 |
| 删除 | POST `/api/tasks/delete` | JSON id；返回 id 和 deleted |
| 批量删除 | POST `/api/tasks/batch-delete` | JSON ids；返回处理数量 |
| 批量更新状态 | POST `/api/tasks/batch-update-status` | JSON ids、completed；返回处理数量 |

细则建议：page 从 1 开始，pageSize 默认 20、范围 1–100；默认按 id 升序；排序仅允许明确列出的字段。title 去除首尾空白后长度为 1–200；id 为正整数；筛选和排序通过安全的持久化查询构建，禁止拼接任意客户端 SQL 片段。

批量 ids 为 1–100 个不同的正整数；空列表、重复 id、越界或缺失资源返回明确错误。一次批量请求全部成功或整体回滚，禁止未说明的部分成功。对分页越界返回空 records 和真实 total，对非法分页参数返回校验错误。

### FR-05 登录、退出与权限

1. 本地账号支持管理员和只读用户；提供登录、退出、获取当前用户接口。登录/退出使用 POST JSON；当前用户查询使用 GET。
2. 使用 Session Cookie，不向前端返回密码或 Session 内部标识；密码以安全散列存储。创建两类账号的初始凭证通过环境变量或首次启动流程设置，不在源码、Golden、测试证据或 README 中放入可用于运行环境的固定密码。
3. Session Cookie 使用 HttpOnly、合适的 SameSite，HTTPS 下使用 Secure；本地 HTTP 开发须有明确配置。写操作启用与 Session 配套的 CSRF 防护，前端请求封装负责传递所需信息。
4. 管理员可执行全部样例功能；只读用户可查询、详情、导出、查看和下载文件，不可新增、修改、删除、批量操作、导入或上传。此最小样例采用共享业务数据，不新增按租户或归属隔离。
5. 未登录返回 401，无权限返回 403；权限在后端执行，前端同步隐藏/禁用操作并处理失效登录。
6. 登录失败不暴露账号是否存在；提供基本失败频率限制。退出立即使当前 Session 失效；建议空闲过期为 30 分钟，作为可配置项。
7. 生成项目必须说明首次设置账号、登录、退出和角色切换的操作；不得因缺少安全的初始密码而自动启用固定弱密码。

### FR-06 CSV 导入导出

1. 首期提供 Task CSV 模板下载、预校验、确认导入和按当前筛选条件导出；导入仅新增，不隐式覆盖已有数据。
2. CSV 使用 UTF-8，明确表头 `title,completed`，规范布尔值、空行、引号、逗号、换行和编码错误的处理；导出确保常见表格工具可读取，并防止公式注入。
3. 预校验返回行号、字段和错误原因，不写入业务记录；确认导入必须重新校验本次内容，不能只信任前端“已预校验”。
4. 建议单次最多 1000 行、文件不超过 2 MiB；任意行非法时整体拒绝，合法时事务性导入。反馈成功数量，不承诺基于相同内容的自动幂等去重。
5. 导出根据授权与筛选条件获取最多 1000 条记录；超过限制明确提示缩小筛选范围，不静默截断。查询/同步导出使用 GET，导入及预校验使用 POST multipart。
6. 文件操作失败返回统一 JSON；成功下载/导出使用正确的媒体类型与 Content-Disposition。

### FR-07 文件上传下载

1. 上传使用 POST multipart，返回 fileId、原始文件名、安全的显示名称、大小、媒体类型及查询/下载地址；元数据与下载 GET 接口分开。
2. 首期本地存储于配置的数据目录，目录不在静态资源根中，文件使用服务端生成的存储名称；数据库保留元数据。不得把客户端文件名当作磁盘路径，不允许覆盖已有文件。
3. 建议单文件 ≤10 MiB，允许 CSV、TXT、PNG、JPEG、PDF；结合扩展名、声明类型和内容检查拒绝不匹配文件。未知类型、超限、空文件及路径穿越输入有明确错误。
4. 下载必须鉴权并执行权限检查，使用 fileId 定位记录，默认附件下载，不提供任意路径读取和上传内容直接执行能力。
5. 元数据写入失败时清理本次上传文件；文件缺失、存储无权限等情况不能伪装成功。服务重启后，已有文件及业务数据仍可访问。
6. 不新增通用文件管理、在线预览或对象存储。此样例不声称提供恶意软件扫描能力。

### FR-08 Vue 最小管理界面

1. 提供登录页、管理布局、当前用户/角色展示与退出入口。
2. Task 页支持筛选、排序、分页、详情、新增/编辑表单、删除确认、多选、批量操作和明确的加载/错误/空状态。
3. 提供 CSV 模板下载、预校验结果、确认导入、导出，以及文件上传、文件列表/元数据和授权下载入口。
4. 前端校验改善体验，后端校验始终生效；401 引导登录，403 展示无权限，敏感操作避免重复提交。
5. API 路径、请求/响应类型和错误处理集中维护；页面不得各自实现另一套请求约定。
6. 保持最小可用的 Element Plus 管理界面，桌面及窄屏下无关键操作被遮挡；不引入第二套完整后台产品。

### FR-09 sg-change 复用与一致性门禁

1. 规划、实现和走查阶段均读取项目内规范版本、样例索引及相关实际文件，记录所引用的路径、版本和摘要，不能仅在提示词中写“遵循模板”。
2. 新增 API 默认参照上述 Controller/Service/DTO/VO、前端 API/页面及测试样例；新增功能同步更新 API 文档和相关测试。
3. 使用项目所记录的模板版本，不静默改用插件最新模板。样例缺失、版本不兼容或引用内容发生漂移时，给出明确阻塞原因和修复选择，不猜测内容或直接覆盖用户文件。
4. 模板一致性通过目录/命名/分层规则、格式与静态检查、契约测试及人工式代码走查共同检查。项目已有风格与模板冲突时，在需求/方案阶段记录差异并取得明确选择。
5. 完成条件包含真实质量结果、走查问题处置和证据对账；保留既有需求、计划、实现、集成、审批等状态约束，不绕过它们直接完成。

### FR-10 生成、验证与状态闭环

1. sg-init 保持离线生成与结构检查，不联网安装或现场执行全部质量任务。报告明确记录当前项目的测试等检查 `not-run`，并区分 Golden 历史验证信息。
2. sg-verify 对生成工程实际执行安装/构建、静态检查、格式检查、测试、覆盖率、真实 HTTP 与功能验证；各检查独立可追踪，不能在新增检查后仍用旧阶段数代表全部通过。
3. sg-change 对当前变更执行对应质量任务。测试通过后源码又变化，相关证据失效，必须重新验证；最终检查应基于格式化后的最终内容。
4. 格式化修改文件后重新执行受影响的检查，最终 format check 无差异。质量检查失败不得自动关闭、归档或标记完成。
5. 取消、超时、环境缺失、依赖下载失败、零测试、关键测试跳过、覆盖率报告缺失、走查失败分别记录；只要必需项未满足就不能给出 PASSED。
6. 沿用现有 Windows/Linux 工具链发现、环境复用、自定义路径询问和本地安装流程；本轮不新增平行环境配置引擎。

## 5. 非功能要求与质量门禁

| 编号 | 要求 | 验收方式 |
| --- | --- | --- |
| NFR-01 兼容性 | 四套 Java 配置在 Windows/Linux 均生成、构建、运行并完成验收；兼容 Java 8 语法及各 Spring 版本差异 | 4 × 2 执行记录；可由本机或 CI 实际运行，未执行的平台保持待验收 |
| NFR-02 静态检查 | 后端风格/静态分析，前端 ESLint/TypeScript 检查均通过，未解决违规不放行 | 保留规则配置、执行命令、输出和退出码 |
| NFR-03 格式 | 前后端一套确定的格式化配置；最终格式检查通过 | 自动格式化后针对最终内容验证 |
| NFR-04 覆盖率 | 后端、前端分别行覆盖率 ≥80%、分支覆盖率 ≥70%，不得取两端平均；最终工程及受影响模块均不得通过排除新增业务代码降低要求 | JaCoCo 等后端报告和前端覆盖率原始报告；记录纳入/排除规则及分母，例外需明确审批 |
| NFR-05 真实测试 | 单元测试、API 契约与集成测试、真实运行功能测试覆盖正常、边界、失败和权限路径 | 非零有效用例、测试明细、HTTP 结果和页面操作证据；脚本存在不等于执行 |
| NFR-06 安全 | 登录、CSRF、401/403、退出失效、角色越权、文件路径/类型/大小及导入安全有专项测试 | 后端强制权限与负向用例，不以隐藏按钮代替鉴权 |
| NFR-07 走查 | 对职责、事务、错误处理、鉴权、文件、模板一致性和测试充分性形成独立于 lint 的逐项结论 | 记录所查源码摘要、发现、严重度、整改和复核；阻断问题关闭后才能完成 |
| NFR-08 可对账 | 证据关联 runId、源码摘要/commit、模板版本、平台工具链、命令、起止时间、退出码、测试数、跳过数、覆盖率与日志路径 | 状态报告与原始 JUnit/Vitest/覆盖率及运行记录交叉核对，任意缺失不误判通过 |
| NFR-09 有界资源 | 分页、批量、CSV、上传均有可配置上限；不把完整文件 Base64 放入普通业务响应 | 边界与超限测试；大于允许值明确拒绝 |
| NFR-10 可维护与隔离 | 不包含本机路径、凭证、node_modules、target、dist、运行数据和上传文件；已有业务工程不自动迁移 | 包与生成物检查、忽略规则及隔离验收 |
| NFR-11 初始化体验 | 保留离线快速生成目标；2–5 秒作为现有常规环境目标，新增功能不使 init 变成安装/测试流程 | 记录机器环境、文件规模和耗时；不能把目标当作已测结论 |

质量执行要求同时覆盖模板发版验收和 sg-change 的最终代码。不同测试层可复用测试设施，但必须说明各自验证了什么；重复调用同一个测试命令不能冒充多种测试完成。

## 6. 验收场景

- AC-01：每种 Java 配置生成后能从项目内找到同一版本的规范、API/页面/测试样例和检查入口；Java 与 Vue 采用批准的风格配置。
- AC-02：未执行 sg-verify 的新项目明确展示“已生成、当前项目未验证”，不会把 Golden 验证结论当成本地测试结果。
- AC-03：登录、当前用户、退出和过期路径可操作；管理员可写，只读用户的写请求由后端返回 403，匿名请求返回 401，错误为统一 JSON。
- AC-04：分页、筛选、排序与 total 正确；CRUD 正常及失败路径、校验错误、资源缺失均与文档及前端一致。
- AC-05：批量操作校验 id 集合，任意非法/缺失项整体失败，验证无部分写入和越权执行。
- AC-06：合法 CSV 能预校验并导入；非法数据返回行级错误且不产生部分数据；按筛选导出与页面结果一致，超限及公式输入有专项验证。
- AC-07：允许类型的文件上传、元数据查询、授权下载、重启访问正确；非法类型、超限、路径穿越、未登录/越权、存储失败和文件缺失返回约定错误。
- AC-08：管理界面能实际完成上述操作，API 层、类型、后端契约一致；包含真实浏览器操作验证，不能用接口测试替代全部页面功能测试。
- AC-09：sg-change 在隔离生成工程中新增一个与 Task 不同的资源功能，能追踪它读取的样例，并产生同风格的后端、前端 API/页面、文档与测试，完成全流程验收。
- AC-10：注入风格违规、测试失败、低覆盖率、关键测试跳过、证据缺失、源码变化、样例缺失和取消/超时，均不能进入成功完成状态；修复并实际重跑后才能放行。
- AC-11：最终源码对应的前后端静态检查、格式检查、测试、覆盖率及代码走查通过；4 套 Java 配置在两种平台均有真实验收证据。缺少平台运行条件时记录未完成，不伪造平台通过。
- AC-12：现有插件回归通过，历史其他语言模板不被本轮意外改变；所有 Golden 记录只在真实验收后更新，原始证据可对账。
