# SpecGate v4.0 需求：init 搭框架，change 做需求，monorepo 并行

- 文档 ID：V4.0-REQ-001
- 状态：已确认（2026-10-20）
- 基线：v3.10.0
- 目标版本：4.0.0

## 0. 一句话

`sg-init` 只做“技术栈选择 → monorepo/submodule 脚手架 → CRUD 样例 → 测试/格式化/走查 → 归档”；需求分析归 `sg-change`；存量仓库用 `--adopt` 只读扫描、确认后原地接入，不移动代码；前后端各自独立 SpecGate、并行开发，归档时再合并到各自 main。

## 2. 根仓库职责

```text
workspace/
├── .specgate/
│   ├── workspace.yaml      # 子模块、栈、契约、并行/合并策略
│   └── state.json          # 根编排状态
├── contracts/openapi.yaml  # 前后端共享契约
├── api/                    # submodule
├── web/                    # submodule
└── README.md
```

- 不建根 REQ、不写业务代码。
- 根 change 记录关联前后端子 change、聚合状态、最终指针更新。
- 跨端需求写在根 change 的 proposal，再拆成两侧 delta。

## 3. sg-init：新项目

### 3.1 对话框（只问技术栈）

- 后端：node / python / java / none
- 前端：vue / react / none
- 预设：node 全栈（api=node + web=react）、vue+node、react+python、java+react

不提问功能/非功能/约束/验收。

### 3.2 生成

1. 根 monorepo + api/web 本地裸仓库 + submodule（相对路径，离线可用）。
2. 每个 submodule：独立 .specgate/config.yaml、state.json；openspec/REQ.md v1.0：REQ-001 搭建框架；openspec/changes/bootstrap/；脚手架 + Item CRUD + 契约 + 测试。
3. 质量流水线（每侧独立）：格式化 → 静态检查 → 测试 → reviewer。
4. 全部通过后归档、合并、根更新指针、IDLE；失败则停 H1_PENDING 并保留报告。

### 3.3 Git 与提交链

```text
根仓库
  git init
  commit  chore(workspace): 初始化 SpecGate monorepo
  git submodule add api / web
  commit  chore(workspace): 添加 api/web 子模块

每个 submodule
  git init（仅新项目）
  branch bootstrap
  commit  feat(mvp): 搭建 <stack> 框架与 Item CRUD
          # 脚手架 + 代码 + 测试 + 质量报告，一个压缩提交
  commit  chore(bootstrap): 归档 MVP 框架变更
  merge --no-ff bootstrap → main
  tag     mvp-bootstrap

根仓库最后
  commit  chore(workspace): 更新 api/web 子模块指针
  tag     mvp-bootstrap
```

- 无变更不产生空提交。
- 重复 sg-init 不重复 git init、不重复 submodule、不重复提交。
- 只有质量/测试/审查全过才产生代码提交与合并。

## 4. sg-init --adopt：存量仓库

### 4.1 只读扫描（确认前零写）

扫描 git 状态、submodule、顶层目录、前后端技术栈、构建/测试命令、已有 .specgate/openspec/REQ.md。分类：

| 类型 | 行为 |
|---|---|
| 已是 v4 | 幂等跳过/修复缺失项 |
| v3 单仓 | 保持 v3，不迁移 |
| 存量 + api/web 独立 git 仓库 | 加为 submodule，原地接入 |
| 存量 + 单个 git 仓库 | 原地接入为 single-repo workspace（不并行），提示并行 monorepo 需单独迁移 |
| 部分初始化 | 补齐缺失项，不覆盖已有 |

扫描报告只存在内存/对话里；确认前不写任何文件。

### 4.2 确认后写入

- 加 .specgate、openspec/、.gitignore。
- REQ.md v1.0：REQ-001 存量系统基线。
- 不生成 CRUD、不移动代码、不覆盖已有文件。
- 质量检查只报告，不阻断。
- Git：不 git init、不重写历史；只提交 SpecGate 资产/报告：chore(specgate): 接入现有项目并写入存量基线；不提交用户未提交改动。
- 重复 --adopt 幂等。

## 7. sg-change（需求归属）

1. 根执行，问改 api / web / 两者。
2. 逐维盘问功能/非功能/约束/验收；确认前零写。
3. 确认后写 REQ 增量、创建根 change + 各侧 sub-change（changeKey 关联）。
4. 各 submodule 独立走 H1 → PLAN → H2 → EXECUTING → INTEGRATING → H3。
5. 前后端并行，锁/worktree/分支按 submodule 隔离。
6. 归档：每侧 integration 合并到自己的 main、应用 specs delta、归档；两侧完成后根更新指针并提交/tag。
7. 单侧 change 不阻塞另一侧。

## 9. 非功能需求

| 编号 | 要求 |
|---|---|
| NFR-1 幂等 | init/adopt/change 重复执行不重复写、不覆盖；显式 --force 才重建 |
| NFR-2 稳定可用 | 失败可恢复；写入原子化；每侧锁隔离；不产生半初始化状态 |
| NFR-3 兼容 | v3 项目不变；单仓/多仓、Windows/Linux、中文/空格路径 |
| NFR-4 零写 | 确认前不写扫描报告/REQ/state/config/代码；取消/异常中止 |
| NFR-5 并行 | 前后端独立锁、worktree、分支；互不阻塞 |
| NFR-6 可追溯 | 每侧报告记录命令、退出码、耗时、reviewer 结论 |
| NFR-7 安全 | 不写凭证；submodule URL 不含 token；不提交用户改动 |
| NFR-8 性能 | init 目标 < 15 分钟（含依赖安装；缓存命中更快） |

## 10. 验收标准

- AC-1 新项目 init 只弹技术栈对话框，不问需求。
- AC-2 根 monorepo + api/web submodule，各自独立 .specgate。
- AC-3 新 submodule 的 REQ.md v1.0 含 REQ-001 搭建框架。
- AC-4 按矩阵生成 CRUD/契约/测试；node 全栈预设可用。
- AC-5 每侧跑格式化/静态/测试/reviewer；失败中止并保留报告。
- AC-6 成功后一个压缩代码提交 + 归档提交 + --no-ff 合并 + tag；根提交指针。
- AC-7 --adopt 扫描零写；确认后写存量基线，不改代码、不生成 CRUD；质量只报告。
- AC-8 --adopt 只提交 SpecGate 资产，不提交用户改动；重复执行幂等。
- AC-9 sg-change 需求确认前零写；确认后创建关联子 change。
- AC-10 前后端并行；各自归档合并；根最后更新指针；单侧不阻塞。
- AC-11 v3 项目行为不变；全量测试通过。

## 11. 明确不做

- 不建根 REQ。
- init 不做业务需求分析。
- 不自动把单仓存量代码移动/拆成 submodule（并行 monorepo 需单独迁移）。
- 不覆盖存量代码，不给存量仓库强塞 CRUD。
- v3 项目不自动迁移。
- 归档前不合并到 main。
- 不提交用户未提交改动。

## 12. 实施阶段

1. **Phase 1**：workspace 核心 —— 技术栈对话框、根 monorepo/submodule、默认 REQ、git 提交链、幂等。
2. **Phase 2**：后端 CRUD 与质量 —— node/python/java 代码、测试、格式化、静态检查、reviewer。
3. **Phase 3**：前端 CRUD 与契约 —— Vue/React 页面、mock/real、Vitest、OpenAPI。
4. **Phase 4**：存量 --adopt 与 workspace sg-change —— 扫描、基线、并行子 change、归档合并。
