# SpecGate v4.3 需求：sg-init 闭环交付（Golden 工程复制模式）

- 文档 ID：V4.3-REQ-001
- 状态：已确认（2026-10-21）；v4.3 第一实施切片完成（2026-10-21，sg-java）
- 基线：v4.2.0
- 目标版本：4.3.0
- 决策来源：2026-10-20 至 2026-10-21 对话
- 适用范围：v4 新建项目的 sg-init；v3 单仓与 --adopt 不在本期范围
- 文档地位：v4.3 的唯一需求真相；与 v4.0、v4.1 冲突时以本文件为准

## 0. 一句话

sg-init 不再安装依赖、不再联网、不再编译；它把一份已经在本机跑通的 Golden 工程复制到目标目录，完成结构校验和 Git 基线，2–5 秒内交付一个可在 IDEA 直接导入、安装、编译、运行的 Java + Vue 全栈项目；代码是否通过检测，由发版前对 Golden 工程的本地验收记录证明。

## 1. 背景与问题

### 1.1 现状

当前 v4.2 的 sg-init 已经能完成“目录扫描 → 技术栈向导 → 依赖选择 → 审批 → 生成脚手架与 Item CRUD → 安装依赖 → 格式化/静态检查/测试 → Git 提交”。但这条链路存在四个结构性问题：

1. 成功判据 fail-open：找不到工具链时质量阶段返回 ok/skipped；质量失败时标记 degraded 但仍提交、合并、写完成标记。
2. 安装依赖被放进 init：网络、代理、镜像、权限、缓存都会让 init 变慢、变脆，而且这些风险并不证明代码更正确。
3. 状态不持久：根与两侧的 state.json 被 gitignore，clone 后 sg-change / sg-status 不可用；init 没有阶段状态，半初始化只能靠猜。
4. 能力与入口脱节：严格的 init-contract / minimal-init / runtime-verification 等实现没有接线，入口使用的是宽松实现。

### 1.2 根因

- 把“生成成功”和“交付可用”混成一个成功状态。
- 把“环境能装”误当成“代码正确”。
- 用文件推断代替显式状态机。
- 一套需求存在两套实现。

### 1.3 本期要解决

- 快：生成 2–5 秒，离线可完成。
- 稳：复制的是已经跑通的工程，不是现场渲染的模板。
- 可交付：IDEA 打开即可安装、编译、运行。
- 不撒谎：未验证就是未验证，不叫成功。

## 2. 目标与非目标

### 2.1 目标

1. sg-init 在空目录中离线复制 Golden 工程，2–5 秒完成，不安装依赖、不联网、不编译。
2. 交付物在 IDEA 中打开即可识别 Maven 工程与 npm 工程，按 README 三步完成安装与运行。
3. “代码通过检测”由发版前对 Golden 工程的本地验收记录证明，而不是由每次 init 现场安装证明。
4. 初始化状态显式、可查询、可恢复；失败不伪装成成功。
5. 前后端各自拥有 change、归档与提交轨迹，最终汇入一个根仓库。

### 2.2 非目标

- 不在 init 内安装依赖、编译、测试或启动。
- 不在 init 内下载 JDK、Maven、Node 或任何工具链。
- 不把 CI 作为需求或交付前提。
- 不生成 Python / Node 后端 / React / Gradle 工程。
- 不支持 submodule 拓扑。
- 不做鉴权、分页、Docker、数据库/缓存/消息队列、生产部署。
- 不改动 v3 单仓与 --adopt 的既有行为。

## 4. 用户流程

### 4.1 初始化

    /sg-init
      1. 只读扫描目标目录（不存在也能观察，但不创建）
      2. 询问 3 项：目标目录、版本档、示例存储
      3. 展示确认页：绝对路径、版本、文件数、Golden 最近验证记录、IDEA 步骤、预计 2–5 秒
      4. 用户确认后，在目标同级的临时目录中复制 Golden、替换项目名、写 .specgate/openspec、做结构校验、git init + commit
      5. 原子改名为目标目录
      6. 输出状态与下一步
      7. 不安装、不联网、不编译

### 4.2 IDEA 打开

    1. 打开根目录
    2. 将 Project SDK 设为所选 JDK（IDEA 可自动下载）
    3. Maven Reload（识别 api/pom.xml 与 api/mvnw）
    4. 在 web 目录执行 npm install（或使用已提交的 package-lock.json）
    5. 运行 api 的 DemoApplication；运行 web 的 npm run dev
    6. 访问 http://127.0.0.1:5173，/api 代理到 8080

### 4.3 可选本地验证

    /sg-verify
      → 安装依赖 → 格式检查 → lint → 类型检查 → 单测 → 构建 → 启动冒烟
      → 通过则 SMOKE_PASSED；失败则 VERIFY_FAILED，代码保留，可重试

## 5. 功能需求

### 5.1 范围与交互

- FR-01 技术栈范围：首版只支持 Java 后端 + Vue 前端；不向用户提供 Python、Node 后端、React、Gradle 选项。
- FR-02 版本矩阵：固定四个版本档，每个档位给出精确版本与前置条件；非法组合在向导层直接拒绝。
- FR-03 向导问题：最多 3 问（目标目录、版本档、示例存储）；其余使用默认值；支持非交互参数以便脚本调用。
- FR-04 确认页：必须展示目标绝对路径、版本档与精确版本、将复制的文件数量、Golden 最近验证日期与结论、IDEA 打开步骤、预计耗时、失败后的行为；支持“返回修改 / 取消”。
- FR-05 确认前零写：确认前不创建目标目录、不写草稿、不写配置文件、不写报告；取消、异常、关闭对话框均视为零写。
- FR-06 目标保护：目标目录已存在且非空时拒绝执行；不使用覆盖、不删除用户文件。

### 5.2 生成

- FR-07 Golden 复制：从 templates/golden/<id>/ 复制 api 与 web 到临时目录；Golden 内不包含 node_modules、target、dist、.git、.idea、本机路径或凭证。
- FR-08 最小替换：只替换项目名、artifactId、README 标题；首版包名固定为 com.example.demo，用户可在 IDEA 中重命名；替换规则必须可枚举、可测试。
- FR-09 结构校验：复制后必须校验必需文件集、pom.xml 与 package.json 可解析、Golden 版本与 golden.json 一致、无未替换占位符、.gitignore 覆盖 node_modules/target；任一项失败即 FAILED。
- FR-10 根文件：按版本档生成根 README、根 package.json、根 scripts；只生成实际存在的端；命令必须与生成物一致。
- FR-11 IDEA 友好：使用标准 Maven Wrapper（.mvn/wrapper + 官方 mvnw/mvnw.cmd），提交 package-lock.json，声明 Node 版本；不提交 .idea。
- FR-12 Git 基线：在临时目录内 git init、提交全部生成物、打 init-baseline tag；成功后随目录改名保留。
- FR-13 初始化报告：写 .specgate/init-report.json，记录 Golden ID、版本、文件数、结构校验结果、Git commit、状态、时间；不记录本机绝对路径以外的敏感信息。

### 5.3 验证与状态

- FR-14 初始化成功定义：Golden 复制完成 + 结构校验通过 + Golden 验证记录有效 = TEMPLATE_VERIFIED；不包含安装、编译、测试。
- FR-15 Golden 验证记录：每个 Golden 提供 golden.json，包含 ID、精确版本、最近验证日期、验证平台、执行命令、结论；缺失或结论非 passed 时状态为 UNVERIFIED。
- FR-16 可选本地验证：/sg-verify 执行安装、格式检查、lint、类型检查、单测、构建、启动冒烟；不得修改生成源码；结果写入 .specgate/verify-report.json。
- FR-17 完整验收：/sg-verify --full 追加真实浏览器 CRUD 与正常重启后数据保留；用于发布/里程碑。
- FR-18 失败语义：生成失败 = FAILED；验证失败 = VERIFY_FAILED；两者都不 merge、不打 tag、不写完成标记；代码与日志保留，可从失败阶段重试。
- FR-19 状态持久化：.specgate/state.json 记录 init 状态、Golden ID、版本、验证状态；state 入库；缺失时从 workspace.yaml + config 重建。
- FR-20 幂等：重复 init 在已完成 workspace 上 skipped；半初始化不覆盖用户文件；失败只清理本次临时目录。

### 5.4 门控与后续

- FR-21 change 门控：sg-change 要求 TEMPLATE_VERIFIED 或更高；UNVERIFIED / VERIFY_FAILED 阻断，并提示 /sg-verify。
- FR-22 发布门控：release/tag 要求 VERIFIED；仅有 TEMPLATE_VERIFIED 不足以发布。
- FR-23 单仓分侧轨迹：api/web 各自拥有 change 包、分支或 scoped commit、归档记录；根上以 --no-ff 合并并打 tag；不生成 submodule/gitlink。
- FR-24 状态查询：sg-status 在 v4 根目录可用，展示初始化状态、Golden ID、版本、验证状态与下一步；不得因 schema 4 报 STATE_INVALID。
- FR-25 命令一致性：所有提示中出现的命令必须真实存在；删除 /sg-env 提示；保留 /sg-verify。

### 5.5 文档与治理

- FR-26 文档单一真相：README、ADR、规格、CHANGELOG 与本文件一致；旧文档标注废弃。
- FR-27 清理：删除或合并未接线的 init 实现（minimal-init、init-contract、runtime-verification、env-tool 等），只保留一条初始化引擎。
- FR-28 测试：npm test 全绿；至少覆盖 Golden 复制、结构校验、替换规则、零写、状态门控；真实构建验证为可选 e2e。
- FR-29 Golden 维护：版本升级时同步更新 Golden 与 golden.json，并记录发版前验收；验收记录保存到 docs/verification/。

## 7. 状态与门控

### 7.1 状态定义

| 状态 | 含义 |
|---|---|
| GENERATED | 文件已复制、结构校验通过，但 Golden 验证记录缺失或无效 |
| TEMPLATE_VERIFIED | 与已验证的 Golden 一致，可创建 change |
| SMOKE_PASSED | 本地 /sg-verify 快验通过 |
| VERIFIED | 完整验收通过，可发布 |
| UNVERIFIED | Golden 无有效验证记录，禁止 change |
| VERIFY_FAILED | 本地验证执行但失败，代码保留 |
| VERIFY_BLOCKED | 缺少 JDK/Node 等前置条件，验证未执行 |
| ABORTED | 用户取消，零写 |

### 7.2 门控矩阵

| 操作 | GENERATED | TEMPLATE_VERIFIED | SMOKE_PASSED | VERIFIED | UNVERIFIED / FAILED |
|---|---|---|---|---|---|
| sg-change | 否 | 是 | 是 | 是 | 否 |
| merge / archive | 否 | 是 | 是 | 是 | 否 |
| release / tag | 否 | 否 | 否 | 是 | 否 |
| /sg-verify | 是 | 是 | 是 | 是 | 是 |

## 8. 验收标准

- AC-01 断网空目录执行 /sg-init，3 问内完成，5 秒内结束，状态为 TEMPLATE_VERIFIED。
- AC-02 确认前零写，包括不创建目标目录；取消/异常后目标目录不存在。
- AC-03 生成物与 Golden 逐字节一致，仅存在 FR-08 声明的替换差异。
- AC-04 IDEA 打开根目录后，按 README 完成 Maven 导入、npm 安装、后端与前端启动。
- AC-05 三个稳定版本档均可复制并打开；preview 档在确认页明确标注。
- AC-06 Golden 无有效验证记录时状态为 UNVERIFIED，sg-change 被拒绝，并提示 /sg-verify。
- AC-07 /sg-verify 失败时状态为 VERIFY_FAILED，代码保留，可只重跑失败阶段，不产生 merge/tag。
- AC-08 新 clone 的仓库 sg-status 正常、sg-change 可创建。
- AC-09 api/web 的 change 独立归档后，根上产生合并 commit 与 tag。
- AC-10 所有提示命令真实存在；不存在 /sg-env 死引用；只剩一套初始化引擎。
- AC-11 npm test 全绿，覆盖 Golden 复制、结构校验、替换、零写与门控。
- AC-12 README/ADR/规格/CHANGELOG 与本文件一致，无相互矛盾。

## 10. 假设、风险与缓解

| 项 | 风险 | 缓解 |
|---|---|---|
| Golden 复制维护 | 3–4 份近似代码需同步 | 版本升级清单 + 发版前逐份验收；必要时用脚本从单一来源再生成 Golden |

## 13. 实施记录（2026-10-21，sg-java）

- 默认仅生成：`sg-init` 不安装依赖、不编译、不启动质量 agent；`--lenient` / `--strict` 显式进入质量流程。
