# SpecGate v3.5 需求：环境预检、按栈工具补齐与质量门禁

- 文档 ID：V3.5-REQ-001
- 状态：Draft，待审查
- 日期：2026-10-19
- 基线：v3.4.0

## 1. 背景

v3.4 已有测试套件（Node `test:json`、pytest、Playwright/Cypress）和延迟安装，但存在缺口：

- 没有统一的仓库环境/插件扫描；formatter 只读 `formatter.command`，不会探测 Prettier/ESLint/Ruff/mypy/tsc。
- 没有 lint 与 typecheck 阶段；Vue/React/TS 没有框架级检查。
- reviewer 不在 review worktree 重跑测试，也没有 lint/typecheck。
- 缺工具时没有“按栈补齐”的路径，只能人工配置。

本需求把 **扫描 → 计划 → 首次执行时安装 → 质量检查 → 审查重跑** 串成闭环。

## 2. 功能需求

### FR-1 环境预检扫描（只读）

- 时机：**H0（新建项目上下文确认后）** 与 **H2（计划冻结前）** 各执行一次；不安装、不改仓库。
- 粒度：monorepo 逐 workspace 扫描，根目录汇总。
- 扫描内容：
  - 运行时：Node/Python 版本、包管理器与 lockfile、workspaces。
  - 质量工具：test/lint/format/typecheck 的配置与 `package.json` scripts。
  - 已装工具：Prettier、ESLint、tsc/vue-tsc、Ruff、mypy、Playwright/Cypress 浏览器。
  - 本地产物：`node_modules`、venv、缓存。
  - CI / git hooks / 编辑器配置。
- 输出 `.specgate/env.json` 与 `.specgate/env-report.md`，提交进仓库（不含密钥）。
- `/sg-status` 增加“环境”段：已就绪、缺失、待安装数量与关键项。
- 扫描失败（无法读配置、版本越界）只记录，不阻断 H0/H2；真正执行时再阻断。

### FR-2 按栈工具矩阵

- **Node 后端**：Prettier、ESLint（flat config）、`tsc --noEmit`（若 TS）。
- **Vue**：Prettier、ESLint + `eslint-plugin-vue`、`vue-tsc --noEmit`。
- **React**：Prettier、ESLint + react 插件、`tsc --noEmit`。
- **Python**：**Ruff（format + lint）** + **mypy**；不引入 Black，避免双格式化器。
- **monorepo**：逐 workspace 选择矩阵；根目录只做汇总与共享缓存。
- **TypeScript**：类型检查失败阻断；Vue 用 `vue-tsc`，Node/React 用 `tsc`。
- 版本范围：Node 18/20/22/24，Python 3.9–3.13；越界在环境报告中标记 `unsupported`。

### FR-3 缺失工具补齐

- H0/H2 只生成“待补齐计划”（包名、版本、配置文件名），**不写 package.json、不安装**。
- 首次真正执行 formatter/lint/typecheck/test 时：
  - 缺失 devDependencies 才写入 `package.json` 并更新 lockfile；
  - 缺失配置才生成最小配置，已有配置不覆盖；
  - 安装命令按 lockfile 选择：`npm ci`、`pnpm install --frozen-lockfile`、`yarn --immutable`；Python 用 venv + `pip install -r` / `uv sync`。
- 生成的最小配置：
  - `prettier.config.mjs`（或 `.prettierrc`）
  - `eslint.config.js`（flat config，含 `eslint-config-prettier`，Vue/React 对应插件）
  - `ruff.toml`（format + lint 规则）
  - `mypy.ini`
  - `tsconfig.json` 仅在缺失且确认 TS 时生成
- 所有新增包与配置写入环境报告，可审计；安装失败阻断当前任务。

### FR-4 质量门禁阶段

任务流水线调整为：

```
implementer → formatter → lint → typecheck → tester → reviewer
```

- **formatter**：先尝试自动修复（Prettier `--write`、Ruff `format`）；修复后仍有未提交改动则提交；报告 `format-report.md`。
- **lint**：ESLint / Ruff check；失败阻断任务，不自动修复（可配置 `--fix` 关闭）。
- **typecheck**：`tsc --noEmit` / `vue-tsc --noEmit` / mypy；失败阻断。
- 命令优先级：`.specgate/config.yaml` 显式配置 > `package.json` scripts > 生成的默认命令。
- 每个阶段独立 agent 调用？formatter 保持独立 agent/worktree；lint/typecheck 作为命令阶段执行，结果写入 runs。
- 报告：`lint-report.md`、`typecheck-report.md`、`format-report.md`，均写入 change 的 `reviews/`。

### FR-5 reviewer 重跑

- reviewer 在独立 review worktree 中重跑：
  - 任务 suite（或集成时全部 suite）；
  - lint；
  - typecheck。
- review worktree 依赖：首次按 lockfile 安装，使用共享包管理器缓存；Python 共享 pip/uv 缓存；不复制任务 worktree 的 `node_modules`。
- 任一失败直接作为 blocking（file/line/evidence 仍需满足 v3.4 校验）。
- 集成审查同样重跑 lint/typecheck/test，blocking 阻断 H3。

### FR-6 环境报告与可观测

- `.specgate/env.json` 结构：
  ```json
  {
    "schemaVersion": 1,
    "workspaces": [
      {"path": ".", "stack": "node|vue|react|python", "runtime": {"node":"22.1.0"}, "packageManager": "pnpm", "tools": {"prettier":"missing","eslint":"ready"}}
    ],
    "missing": ["prettier"],
    "plan": ["npm install -D prettier"],
    "unsupported": []
  }
  ```
- runs 记录新增阶段：formatter、lint、typecheck，含命令、退出码、耗时、报告路径。
- `/sg-status --verbose` 显示质量阶段时间线。

## 3. 非功能需求

- 扫描 <2 秒（不含网络）；离线可扫描。
- 安装只在首次真正执行时发生；同一 lockfile 不重复安装。
- 不修改全局环境；不全局安装包。
- 报告/日志脱敏；不包含 token/密钥。
- 幂等：重复扫描/执行不重复写配置、不重复装同版本依赖。
- 失败可诊断：环境报告给出缺失包、命令、配置文件路径与修复建议。
- 配置生成不覆盖已有文件；冲突时报告并跳过。

## 4. 验收标准

- AC-1：H0 与 H2 各生成 `.specgate/env.json` 与 `env-report.md`，不安装依赖、不改 `package.json`。
- AC-2：Node 后端/ Vue/ React/ Python/ monorepo 能识别对应工具需求；版本越界标记 `unsupported`。
- AC-3：首次执行时按 lockfile 安装；缺失 devDeps 与配置被补齐并记录；重复执行不重复安装。
- AC-4：任务流水线按 implementer→formatter→lint→typecheck→tester→reviewer 执行；lint/typecheck 失败阻断。
- AC-5：Vue 用 vue-tsc、Node/React 用 tsc、Python 用 Ruff+mypy；不出现 Prettier/Ruff 同时接管 Python 格式化。
- AC-6：reviewer 在 review worktree 重跑 test+lint+typecheck；失败作为 blocking。
- AC-7：`/sg-status` 显示环境段；runs 记录 formatter/lint/typecheck。
- AC-8：单测覆盖扫描、补齐计划、工具选择、阻断、review 重跑；`node --test` 全绿。

## 5. 实施切片

1. `env-scan` 模块：栈识别、工具矩阵、env.json/md（只读）。
2. H0/H2 接入扫描 + status 展示。
3. `toolchain` 模块：缺失计划、最小配置生成、首次安装。
4. formatter 改为自动命令选择；新增 lint/typecheck 阶段与报告。
5. reviewer 重跑 test/lint/typecheck（review worktree 依赖安装与缓存）。
6. 测试与文档。

## 6. 明确不做

- 不做全局工具安装。
- 不做 Black 与 Ruff 并存。
- 不自动修改已有 lint/format 配置。
- 不做远程 CI 执行，只在本机 worktree。
- 不做多版本 Node/Python 自动下载（只用本机已装版本，越界报 unsupported）。
