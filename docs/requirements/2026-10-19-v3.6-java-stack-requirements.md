# SpecGate v3.6 需求：Java 后端技术栈支持

- 文档 ID：V3.6-REQ-001
- 状态：Draft，待审查
- 日期：2026-10-19
- 基线：v3.5.0
- 验证方式：**不跑 sg change 流程**，直接生成样例工程并执行构建/测试/质量命令，快速反馈

## 1. 背景

当前 SpecGate 已支持 Node/Vue/React/Python，但 Java 后端完全未覆盖：

- 环境扫描不识别 JDK、Maven、Gradle；
- 初始化没有 Java/Spring Boot 脚手架；
- 工具链不会生成 Spotless/Checkstyle/SpotBugs 配置；
- 测试套件不解析 Surefire/Gradle JUnit XML；
- reviewer 没有 Java 编译/静态检查结果可重跑。

本需求补齐 Java 后端从初始化、环境预检、构建、测试、格式化、静态检查到审查的完整支持，但本次只做**直接样例验证**，不执行 SpecGate 的 H1/H2/H3 流程。

## 2. 技术范围

### 2.1 JDK

- 仅支持真正 LTS：**JDK 8、11、17、21**。
- **JDK 13 不纳入**（非 LTS）。
- 只探测本机 JDK，不自动安装；缺失时阻断并报告。
- 探测来源：`JAVA_HOME`、`java -version`、`mvn -version`、`gradle -version`、`~/.m2/toolchains.xml`、SDKMAN 目录（只读）。

### 2.2 Spring Boot

- 支持 **2.7.x** 与 **3.x 最新稳定版**。
- 不支持 Spring Boot 4.x（本次范围外）。
- 严格兼容矩阵：
  - Boot 2.7：JDK 8 / 11 / 17；
  - Boot 3.x：JDK 17 / 21；
  - 其他组合直接拒绝并给出可选项。
- 默认新项目：**JDK 8 + Maven + Spring Boot 2.7.x**。
- 初始化澄清阶段可选择其他组合；选择后按矩阵校验。

### 2.3 构建工具

- Maven：Wrapper **3.9.x**；Gradle：Wrapper **8.x**。
- 优先使用项目自带 `mvnw` / `mvnw.cmd` / `gradlew` / `gradlew.bat`；缺失时生成 wrapper。
- 存量多模块仓库：支持扫描与构建（`mvn verify` / `gradle check`），不要求初始化生成多模块。
- 新项目脚手架：单模块。

## 3. 功能需求

### FR-1 环境扫描

- 识别 Java 后端 workspace：`pom.xml`、`build.gradle`、`build.gradle.kts`、`settings.gradle`。
- 记录：
  - JDK 版本、JAVA_HOME、来源；
  - Maven/Gradle 版本与 wrapper 是否存在；
  - Spring Boot 版本（从 pom/build 解析）；
  - Spotless/Checkstyle/SpotBugs 插件与配置是否存在；
  - `mvnw`/`gradlew` 是否可执行。
- 输出进 `.specgate/env.json` / `env-report.md`，并显示在 `/sg-status`。
- 违规组合标记 `unsupported`，不自动修正。

### FR-2 新项目脚手架

生成最小可运行 Spring Boot 应用：

- 构建文件：
  - Maven：`pom.xml` + `mvnw` + `.mvn/wrapper/*`
  - Gradle：`build.gradle(.kts)` + `gradlew` + `gradle/wrapper/*`
- 代码：
  - `Application.java`（`@SpringBootApplication`）
  - `HealthController` 或 Actuator `/health`
  - `application.yml`
- 测试：
  - JUnit 5 + AssertJ + Mockito + `spring-boot-starter-test`
  - 至少一个 `/health` MockMvc 测试
- 质量插件：
  - Spotless（google-java-format）
  - Checkstyle
  - SpotBugs
  - Maven 绑定 `verify`；Gradle 绑定 `check`
- 默认 `groupId` / `artifactId` / 包名由上下文或默认值决定。

### FR-3 工具链与依赖

- 首次执行时：
  - 生成缺失的 wrapper；
  - 生成 Spotless/Checkstyle/SpotBugs 配置（不覆盖已有配置）；
  - 通过 wrapper 下载依赖，使用本地 Maven/Gradle 缓存。
- 不全局安装 Maven/Gradle/JDK。
- 依赖下载失败、wrapper 下载失败、JDK 缺失：阻断并给出修复命令。

### FR-4 测试适配

- Maven：解析 `target/surefire-reports/*.xml`（及 failsafe）。
- Gradle：解析 `build/test-results/test/*.xml`。
- 转换为 SG report：
  - `id`、`ac`（从测试名中的 `[AC-xxx]` 提取）、`status`、`file`。
- 无 XML、解析失败、用例为 0：按失败处理。
- 多模块：逐模块聚合报告。

### FR-5 格式化与静态检查

- Spotless：`spotless:check`（Maven）/ `spotlessCheck`（Gradle）。
- Checkstyle：`checkstyle:check` / `checkstyleMain`。
- SpotBugs：`spotbugs:check` / `spotbugsMain`。
- 全部失败阻断；格式化不自动改写（避免任务 diff 污染），只报告。
- 报告写入 `.specgate/runs/java-<task>-<stage>.md`。

### FR-6 审查

- reviewer 在 review worktree 中重跑：
  - `mvnw verify` 或 `gradlew check`（含编译、测试、静态检查）；
  - 解析测试报告与质量报告。
- 任一失败作为 blocking；blocking 仍需 file/line/evidence。

## 4. 非功能需求

- 平台：Windows 与 Linux。
- 构建时间目标：<5 分钟（不含首次依赖下载）。
- 不修改全局环境；不全局安装 JDK/Maven/Gradle。
- JDK/Maven/Gradle 探测只读。
- 报告与日志脱敏；不包含凭证。
- 依赖缓存复用；同一 lock/版本不重复下载。
- 配置生成不覆盖已有文件；冲突时报告并跳过。
- 确定性：同一 JDK/构建文件生成相同命令与报告结构。

## 5. 验收标准

- AC-1：环境扫描识别 Java 仓库、JDK 版本、Maven/Gradle、Boot 版本；非法组合标记 `unsupported`。
- AC-2：默认生成 JDK8+Maven+Boot2.7 单模块工程，包含 `/health` 与 JUnit5 测试。
- AC-3：可选择 JDK17+Gradle+Boot3.x 生成工程；JDK8+Boot3 被拒绝。
- AC-4：Maven `verify` 与 Gradle `check` 均执行 compile/test/spotless/checkstyle/spotbugs。
- AC-5：Surefire/Gradle JUnit XML 被正确转换为 SG report，AC 标签可被识别。
- AC-6：Spotless/Checkstyle/SpotBugs 任一失败时阻断。
- AC-7：review worktree 能重跑 `verify`/`check` 并把失败作为 blocking。
- AC-8：不自动安装 JDK；缺失时明确报错。
- AC-9：两套样例（JDK8+Maven+Boot2.7、JDK17+Gradle+Boot3.x）在 Windows 上真实跑通。
- AC-10：单元测试覆盖版本矩阵、报告解析、插件生成；`node --test` 全绿。

## 6. 验证方式（本次）

不执行 sg change 流程；直接：

1. 生成 JDK8+Maven+Boot2.7 样例，运行 `mvnw verify`。
2. 生成 JDK17+Gradle+Boot3.x 样例，运行 `gradlew check`。
3. 检查测试报告转换、Spotless/Checkstyle/SpotBugs 阻断、环境扫描输出。
4. 记录命令、耗时、失败原因。

## 7. 明确不做

- 不支持 JDK 13/非 LTS。
- 不支持 Spring Boot 4.x。
- 不自动安装 JDK。
- 不生成多模块父工程（存量多模块只构建）。
- 不做 Java 专属 reviewer agent；复用现有 reviewer。
- 不执行 sg H1/H2/H3 流程。

## 8. 实施切片

1. Java 检测与版本矩阵（env scan + 校验）。
2. Maven/Gradle 脚手架与默认组合。
3. wrapper/插件配置生成与依赖安装。
4. Surefire/Gradle JUnit XML 适配。
5. Spotless/Checkstyle/SpotBugs 阶段与阻断。
6. review worktree 接入 `verify`/`check`。
7. 两套样例真实验证与测试。

### 9.4 已知边界

- 生成的 `mvnw` / `gradlew` 是**最小脚本**，调用系统 Maven/Gradle；不是完整 Wrapper 分发包。真实 CI 应替换为官方 Wrapper。
- JDK 只探测，不自动安装；本机已验证 JDK 8/17。
- Spring Boot 4.x 未支持。
- 存量多模块仓库可检测/构建，但脚手架不生成多模块父工程。
- `gradle check` 前需要先 `spotlessApply` 或代码本身符合 google-java-format；本次样例先执行了 `spotlessApply`。
