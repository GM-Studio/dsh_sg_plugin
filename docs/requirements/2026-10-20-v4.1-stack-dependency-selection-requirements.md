# SpecGate v4.1 需求：sg-init 技术栈向导、依赖选择与质量审批

- 文档 ID：V4.1-REQ-001
- 状态：已确认（2026-10-20）；实现版本 4.1.0
- 基线：v4.0.0
- 目标版本：4.1.0
- 决策来源：2026-10-20 对话第 1–3 轮问答
- 适用范围：v4 新建项目的 sg-init；v3 单仓与 --adopt 不在本期范围
- 实施约束：2026-10-20 确认；实现与测试已完成，详见第 14 节

## 0. 一句话

sg-init 在 v4 新建项目时，按“端 → 语言/运行时 → 构建工具/包管理器 → 框架 → 必选依赖 → 可选依赖 → 汇总审批”的向导收集选择；用内置模板与版本化依赖目录生成可运行工程；安装与质量阶段需一次汇总审批，未批准则只生成完整声明、配置和代码，跳过安装与执行。

## 1. 背景与现状

### 1.1 现状

v4 的 sg-init 目前已经打通：

1. 扫描目录，识别空目录、v3、v4、存量仓库。
2. 询问 backend（node/python/java/none）与 frontend（vue/react/none）。
3. 仅当 backend=java 时，追加 JDK、Maven/Gradle、Spring Boot 三个问题。
4. 曾询问功能/非功能/约束/验收并做需求确认；v4.1 已移除这四问。
5. 弹一次“依赖与质量审批”，但审批结果当前没有真正传给 buildWorkspace，跳过逻辑未生效。
6. 创建 workspace 布局、默认 REQ、脚手架、Item CRUD、测试，执行质量阶段，提交并接入 submodule。

相关实现位置：

- src/v4/init.js：向导入口、Java 问题、审批问题。
- src/v4/workspace.js：workspace.yaml、side 选择、布局。
- src/v4/build.js：脚手架写入、质量阶段、git 提交。
- src/v3/init.js：各栈最小脚手架与 Java 模板。
- src/v4/frontend-code.js：Vue/React 最小前端模板。

### 1.2 差距

- Python、Node、前端没有版本、框架、包管理器、语言级别等选择。
- Java 只有三个问题，没有依赖与插件选择；JDK 13 未进入选项。
- 没有依赖目录，也没有“必选/可选/预设”的概念。
- 生成物是最小示例，不是主流脚手架：Node 用原生 http，Python 用标准库 http.server。
- 质量审批只有一个总开关，且未驱动实际跳过。
- 没有技术栈/依赖/命令/审批/退出码的结构化报告。
- 现有 v4 仍会询问功能/非功能/约束/验收四维需求；本期移除这四问，最终审批页直接确认技术栈与依赖。

### 1.3 问题定义

用户选完语言后，无法表达“我要 JDK 21 + Gradle + Spring Boot 4 + JPA + Flyway”这类真实组合；生成出来的工程也不包含对应依赖与质量工具。用户还希望安装依赖、跑格式化/检查/测试/走查之前，先看到将执行什么，并由自己决定是否批准。

## 2. 目标与非目标

### 2.1 目标

- G1：把技术栈选择升级为按端、按语言条件展开的向导，覆盖 Java/Python/Node 后端与 Vue/React 前端。
- G2：为每个栈提供必选依赖（锁定）与可选依赖/插件（多选），并提供最小/推荐/全量预设。
- G3：依赖与版本来自仓库内置的版本化目录，选择与生成阶段不依赖网络，结果可复现。
- G4：安装依赖、格式化、静态检查、测试、自动化走查前，展示一次汇总审批；批准才执行。
- G5：未批准时仍生成完整工程声明、配置与代码，质量阶段标记 SKIPPED，用户可稍后手动安装。
- G6：批准后失败可降级：继续生成并提交代码，init 返回成功但标记 degraded，报告保留失败命令与退出码。
- G7：生成物、选择、审批、命令、结果可追溯；重复 init 幂等。

### 2.2 非目标

- 不改 v3 单仓 init 的行为。
- 不改 --adopt 的扫描、基线与“不覆盖存量代码”语义。
- 不在本期调用 Spring Initializr、create-vite 等官方生成器。
- 不在选择阶段实时查询 npm/PyPI/Maven 仓库。
- 不增加 Next.js、Nuxt、Angular、Svelte、Solid。
- 不增加 FastAPI/Flask/Django 之外的 Python 框架。
- 不增加 Express/Fastify/NestJS 之外的 Node 框架。
- 不引入人工 Review 门控；自动化走查只出报告，不阻塞。
- 不支持用户输入任意自定义包；本期只从目录选择。
- 不实现可选依赖对应的完整业务功能（鉴权流程、数据库迁移、消息消费等），只生成依赖、最小配置和示例。
- 不改变 sg-change、H1/H2/H3 门控语义。
- 不自动迁移已有项目。

## 4. 功能需求

### FR-1 向导流程与条件分支

#### FR-1.1 流程

    1. 扫描目录（只读），判定是否为空目录；非空或已有 .specgate 时按现有 v4 规则处理。
    2. 选择拓扑：backend = java/python/node/none，frontend = vue/react/none；至少一端不为 none。
    3. 按端展开技术栈问题：
       - Java：JDK → 构建工具 → Spring Boot → 必选依赖 → 可选依赖。
       - Python：Python 版本 → Web 框架 → 包管理器/依赖文件 → 必选依赖 → 可选依赖。
       - Node：Node 版本 → 包管理器 → JS/TS → 框架 → 必选依赖 → 可选依赖。
       - Vue/React：框架 → 构建工具（Vite）→ JS/TS → 必选依赖 → 可选依赖。
    4. 不做功能/非功能/约束/验收四维需求盘问；v3 init 的行为保持不变。
    5. 展示最终确认与审批页：按端紧凑列出语言/运行时、构建工具、框架、必选/可选依赖与插件；超长列表截断。
    6. 用户确认该页即最终审批：批准则安装/执行质量，跳过则只生成代码。
    7. 生成 workspace 布局、REQ、工程文件、测试、报告。
    8. 若批准，执行安装与质量阶段；否则跳过。
    9. 按现有 v4 提交链提交、归档、接入 submodule。

#### FR-1.2 交互规则

- 每一步只显示与已选值相关的选项；不相关的问题不出现。
- 修改上游选择后，下游选项与已选依赖必须重新校验；失效项要显式提示，不得静默丢弃。
- 支持“返回修改”；返回时不写任何文件。
- 取消向导视为不生成；不产生半初始化状态。
- 汇总页必须列出被自动取消的可选项及原因。
- 现有 preset（node-fullstack、vue-node、react-python、java-react、java-api、python-api、node-api、vue-only、react-only）保留；preset 只决定拓扑，技术栈细节仍按向导确认。

#### FR-1.3 零写边界

- 在用户确认最终汇总之前，不写 workspace、REQ、config、代码、报告。
- 审批页本身不写文件。
- 用户选择“跳过，仅生成代码”后，才进入生成阶段。

### FR-2 Java 技术栈

#### FR-2.1 选项

- JDK：8、11、13、17、21。
- 构建工具：Maven、Gradle。
- Spring Boot：2.7.x、3.x、4.x。
- 版本粒度：用户选大版本线；目录内锁定该线最新已验证 patch，并记录到报告。
- JDK 13 标注“非 LTS，仅兼容性保留”；不推荐新项目使用。

#### FR-2.2 兼容矩阵

| JDK | Boot 2.7.x | Boot 3.x | Boot 4.x | 说明 |
|---|---|---|---|---|
| 8 | 支持 | 不支持 | 不支持 | 仅 2.7 |
| 11 | 支持 | 不支持 | 不支持 | 仅 2.7 |
| 13 | 支持 | 不支持 | 不支持 | 非 LTS，显示警告 |
| 17 | 支持 | 支持 | 支持 | 推荐 |
| 21 | 条件支持 | 支持（3.2+） | 支持 | 2.7 仅目录验证 patch；默认推荐 3.x/4.x |

- 选择 JDK 8/11/13 时，Boot 3.x/4.x 必须禁用并显示原因。
- 选择 Boot 3.x/4.x 时，JDK 8/11/13 必须禁用。
- 选择 JDK 21 + Boot 2.7 时，显示“条件支持”，并要求目录中存在已验证 patch；否则禁用。
- 矩阵以目录数据为准；实现时需按 Spring 官方支持范围复核并写入测试。

#### FR-2.3 必选依赖与插件

- Web：spring-boot-starter-web。
- 校验：spring-boot-starter-validation。
- 运维：spring-boot-starter-actuator。
- 测试：spring-boot-starter-test。
- 质量插件：Spotless、Checkstyle、SpotBugs、JaCoCo、Surefire（Gradle 为对应插件）。
- 构建包装器：Maven Wrapper 或 Gradle Wrapper。
- 生成 Health 接口与 Item CRUD 测试，确保必选依赖可运行。

#### FR-2.4 可选依赖类别

- 持久化：Spring Data JPA、H2、PostgreSQL、MySQL、Flyway、Liquibase。
- 生产力：Lombok、MapStruct。
- 安全：Spring Security。
- API 文档：springdoc-openapi。
- 运维与集成：Redis、Spring Cache、Kafka、Mail、WebSocket。
- 测试：Testcontainers。
- 部署：Dockerfile、docker-compose（仅生成示例，不启动容器）。

- ORM/迁移/数据库驱动之间如存在冲突，由目录声明互斥组，UI 只允许单选或阻止冲突组合。
- 选中 JPA 时默认带 H2；选 PostgreSQL/MySQL 时再追加对应驱动。
- 可选依赖只生成依赖、配置项和最小示例，不实现完整业务。

#### FR-2.5 构建工具差异

- Maven：pom.xml、mvnw、mvnw.cmd、.mvn/wrapper。
- Gradle：build.gradle、settings.gradle、gradlew、gradlew.bat、gradle/wrapper。
- 同一组质量能力在两种构建工具下都要有等价配置；目录中分别记录命令。
- 不因构建工具不同而改变必选依赖集合。

### FR-3 Python 技术栈

#### FR-3.1 版本与框架

- Python 3：3.10、3.11、3.12、3.13；默认 3.12。
- Python 2：仅 2.7，标注 EOL；默认不选。
- Web 框架：FastAPI、Flask、Django。
- Python 2.7 下 FastAPI 不可用；只允许 Flask 1.1.4 或 Django 1.11.29。
- Python 2.7 下不生成 pyproject.toml，不支持 uv/Poetry；只生成 requirements.txt。
- Python 2.7 下质量工具降级为 Python 2 可用的旧版：pytest 4.6、flake8、autopep8；不使用 Ruff/Black/mypy。
- Python 2.7 必须显示醒目的 EOL 警告：无安全更新、包索引可能不可用、仅尽力保证可生成。

#### FR-3.2 包管理器与依赖文件

- 默认：pip + venv + requirements.txt。
- 可选：Poetry + pyproject.toml、uv + pyproject.toml；仅 Python 3 可用。
- 选择 Poetry/uv 时仍生成 requirements.txt 作为兼容入口，或明确说明二选一；默认生成所选管理器的文件。
- 锁文件只在批准并成功安装后生成；跳过时没有锁文件，报告标注未安装。

#### FR-3.3 必选依赖

- FastAPI：fastapi、uvicorn[standard]、pydantic、pydantic-settings、httpx、pytest、pytest-cov、ruff。
- Flask：flask、python-dotenv、pytest、pytest-cov、ruff。
- Django：django、djangorestframework、pytest、pytest-django、ruff。
- 生成 Health 接口、Item CRUD、对应测试；Django 模板默认使用 DRF 提供 API。
- 如用户不需要 DRF，应选择 Flask/FastAPI，或等后续版本提供纯 Django 模板。

#### FR-3.4 可选依赖类别

- 持久化：SQLAlchemy、Alembic、psycopg、PyMySQL。
- 配置与校验：pydantic-settings、python-dotenv。
- 缓存与队列：redis、celery。
- 安全：passlib、python-jose、itsdangerous。
- 测试与质量：pytest-cov、mypy、pre-commit、httpx。
- 部署：Dockerfile、docker-compose、gunicorn。
- 互斥组示例：SQLAlchemy 与 Django ORM 不同时出现；本地开发数据库驱动单选。

### FR-4 Node 后端技术栈

#### FR-4.1 版本与工具

- 包管理器：pnpm 默认；npm、yarn 可选。
- 语言：TypeScript 默认；JavaScript 可选。
- 框架：Express、Fastify、NestJS。
- NestJS 必须使用 TypeScript；选 NestJS 时 JavaScript 选项禁用。
- 包管理器决定 lockfile：pnpm-lock.yaml、package-lock.json、yarn.lock；只在安装后生成。

#### FR-4.2 必选依赖

- Express：express、zod、cors、dotenv、pino；测试用 vitest、supertest；质量用 eslint、prettier；TypeScript 时加 typescript、tsx、@types/node、@types/express、@types/cors。
- Fastify：fastify、@fastify/cors、@fastify/sensible、zod；测试用 vitest；质量用 eslint、prettier；TypeScript 依赖同上。
- NestJS：@nestjs/core、@nestjs/common、@nestjs/platform-express、reflect-metadata、rxjs；测试用 jest、ts-jest、supertest；质量用 eslint、prettier、typescript。
- 生成 Health 接口、Item CRUD、测试与启动脚本。
- 运行脚本至少包含 dev、build、start、test、lint、format。

#### FR-4.3 可选依赖类别

- 持久化：Prisma、Drizzle、TypeORM、Mongoose；对应 PostgreSQL/MySQL/SQLite/MongoDB 驱动。
- 校验与配置：zod、dotenv。
- 安全：helmet、cors、rate-limit。
- 文档：swagger/OpenAPI。
- 可观测：pino、prom-client。
- 缓存与队列：redis、bullmq。
- 部署：Dockerfile、docker-compose。
- ORM 互斥组：Prisma/Drizzle/TypeORM/Mongoose 只能选一个主 ORM；允许“无 ORM”。

### FR-6 依赖目录

#### FR-6.1 形态

- 目录放在仓库内，建议路径：assets/specgate/catalog/。
- 模板放在仓库内，建议路径：assets/specgate/templates/。
- 目录与模板随插件版本发布；init 不联网拉取。
- 目录必须有 catalogVersion；报告记录该版本，便于复现。

#### FR-6.2 条目字段

每个依赖至少包含：

- id：稳定标识。
- label：展示名。
- category：runtime、validation、test、lint、format、persistence、security、docs、observability、deploy 等。
- required：布尔；true 时 UI 锁定，不可取消。
- version：固定版本或版本范围；由目录锁定。
- scope：compile、runtime、test、dev、optional 等。
- frameworks：适用的框架列表。
- versions：适用的语言/框架版本。
- group：互斥组或单选组。
- conflicts：冲突依赖 id。
- install：安装命令模板（仅用于审批页展示与执行）。
- description：一句话用途。
- docs：可选文档链接。

#### FR-6.3 预设

- 每个栈/框架提供 minimal、recommended、full 三档。
- 默认 recommended。
- minimal：只含运行、测试、格式化、静态检查的最小集合。
- recommended：在 minimal 上增加主流生产力/文档/测试增强。
- full：目录内所有兼容可选项；仍受互斥组限制。
- 用户切换预设后，可逐项调整；手动调整后预设标记为 custom。
- 必选项在任何预设下都不可取消。

#### FR-6.4 校验

- 选择阶段做静态校验：版本、框架、构建工具、互斥组、必选项、至少一个测试/检查/格式化工具。
- 不通过时禁用选项并显示原因，不允许带着无效组合进入汇总。
- 修改上游选择后重新校验；失效的可选项在汇总页列出。
- 目录加载失败、版本缺失、模板缺失属于硬错误，不进入生成。

#### FR-6.5 扩展方式

- 新增语言/框架/依赖时，只改目录、模板和适配器，不改向导主流程。
- 适配器负责：生成文件、给出安装/质量命令、解析结果。
- 新增栈必须有目录条目、模板、命令适配器、单元测试与 golden 文件。

### FR-7 审批页

#### FR-7.1 触发时机

- 技术栈与依赖选择完成后；不再单独做需求确认。
- 在任何安装、格式化、静态检查、测试、走查命令执行之前。
- 审批页只读，不写文件。

#### FR-7.2 展示内容

按端分组，紧凑展示，必须能在一次弹窗内读完：

- 端与角色：api/web。
- 语言与运行时、构建工具/包管理器、框架。
- 必选依赖与插件：标签列表；超过 5 个时只显示前 5 个 + “共 N 个”。
- 可选依赖与插件：同上；未选时显示“（无）”。
- 预设与 custom 标识。
- 一行执行摘要：安装依赖 → 格式化 → 静态检查 → 测试 → 内置走查。
- 网络与失败策略各一行。
- 被自动取消的选项最多列 3 个，其余折叠为数量。

硬限制：正文不超过 20 行或 1200 字符；不展开完整命令、版本号、cwd 和预计耗时。完整命令与版本只写入报告。

#### FR-7.3 选项

- 批准并执行。
- 跳过，仅生成代码。
- 返回修改。

#### FR-7.4 默认与异常

- 用户选择“跳过”、关闭弹窗、问答超时、无问答器：一律按“跳过”处理。
- 跳过不视为失败；质量状态为 skipped，degraded=false。
- 一次审批覆盖 api+web；不提供逐端勾选执行。
- 批准后记录审批时间、范围、决策；报告可追溯。

### FR-8 生成物

#### FR-8.1 无论是否批准都生成

- 根 workspace.yaml：拓扑、每端 stack、版本、框架、依赖 id、预设、目录版本、审批状态。
- 每端 .specgate/config.yaml、state.json、openspec/REQ.md v1.0。
- 框架工程文件：pom.xml/build.gradle、package.json、requirements.txt/pyproject.toml 等。
- 源码：Health 接口、Item CRUD、启动入口、配置。
- 测试：至少覆盖 Health 与 Item CRUD 的关键路径。
- 质量配置：Spotless/Checkstyle、ESLint/Prettier、Ruff、pytest 配置等。
- docs/mvp-scaffold-report.md 与 .specgate/init-report.json。
- README、.gitignore、.env.example（不含密钥）。

#### FR-8.2 仅批准后生成

- 依赖安装产生的 node_modules、.venv、target、build 等目录。
- lockfile：pnpm-lock.yaml、package-lock.json、yarn.lock、poetry.lock、uv.lock、requirements 锁文件等。
- 质量命令的输出与格式化改动。
- 走查报告。

#### FR-8.3 可选依赖的生成深度

- 只写依赖声明、最小配置、示例文件/注释。
- 不实现完整鉴权、数据库迁移、消息消费、缓存策略、CI 部署。
- 报告中明确“已声明但未实现”的边界，避免用户误以为功能已完成。

#### FR-8.4 不写内容

- 不写真实密钥、token、证书。
- 不写用户主目录配置。
- 不覆盖已有用户文件；已存在文件按现有 writeScaffold 规则跳过并记录。

### FR-9 执行、失败与降级

#### FR-9.1 执行顺序

每端独立执行：

    1. install
    2. format（自动修复）
    3. lint/static
    4. test
    5. review（只出报告）

- 端与端之间互不阻塞；api 失败不阻止 web 继续。
- 同一端某阶段失败，停止该端后续质量阶段，标记 degraded，继续生成/提交。
- review 不阻塞；即使报告有问题，也不触发 degraded。

#### FR-9.2 结果状态

- passed：批准且全部阶段成功。
- skipped：未批准或主动跳过；未执行任何安装/质量命令。
- degraded：批准后至少一个阶段失败；init 仍返回成功。
- failed：生成/写入/git 等硬失败；init 返回失败。

#### FR-9.3 降级行为

- init 返回 ok=true、degraded=true，并带 warnings。
- 继续生成剩余文件、写报告、提交代码。
- 提交信息加 [degraded] 标记，报告记录失败阶段、命令、退出码、耗时、stdout/stderr 摘要。
- 不自动重试；用户修正后可重跑 init 或手动执行命令。
- 安装失败时不生成 lockfile；依赖声明仍保留。
- 硬失败（模板缺失、目录损坏、git 提交失败）不回滚已写文件，但必须保留报告并返回 ok=false。

#### FR-9.4 超时

- 安装类命令默认 10 分钟；格式化/检查/测试默认 5 分钟；review 默认 5 分钟。
- 超时按失败处理，进入 degraded。
- 具体超时值放入目录/配置，允许后续调整。

### FR-10 报告与可追溯

#### FR-10.1 人类可读报告

docs/mvp-scaffold-report.md，至少包含：

- 生成时间、目录版本、模板版本。
- 拓扑与每端技术栈。
- 必选/可选依赖及版本。
- 预设与 custom 标识。
- 审批决策与时间。
- 每条命令的 cwd、命令、退出码、耗时、输出摘要。
- skipped/degraded 原因。
- 下一步建议（手动安装命令、失败修复建议）。

#### FR-10.2 机器可读报告

.specgate/init-report.json，至少包含：

- schemaVersion、timestamp、catalogVersion、templateVersion。
- workspace、sides。
- selections：语言、版本、构建工具、框架、包管理器、语言级别。
- dependencies：required/optional、id、version、scope。
- approval：decision、scope、timestamp、interactive。
- commands：phase、command、cwd、exitCode、durationMs、status、outputExcerpt。
- quality：status、degraded、skipped、failedStage。
- warnings。

#### FR-10.3 安全

- 不记录密钥、token、cookie、完整环境变量。
- 输出摘要截断，避免把敏感信息写入报告。
- 命令必须来自目录/模板，不允许把用户输入拼进 shell。

### FR-11 幂等与恢复

- 重复 init 已完成的 v4 工作区：按现有逻辑幂等跳过，不重复提交、不重复 submodule。
- 部分初始化：只补缺失项，不覆盖已有文件；报告记录 skipped 文件。
- 同一选择重复生成：文件内容稳定；时间戳、报告时间等允许变化。
- 显式 --force 才允许重建；没有 --force 不得删除用户文件。
- 失败后重跑：保留现场，按报告提示修复；不得产生重复 commit 或半初始化状态。

### FR-12 非交互与 CI

- 非交互环境必须显式提供 backend/frontend 或 preset；缺少必要参数时报错，不猜测。
- 无问答器时审批默认跳过；报告标记 interactive=false、quality.status=skipped。
- 非交互模式不得自动安装依赖或执行质量命令。
- 所有选择与结果仍写入 workspace.yaml 与报告。

### FR-13 扩展性

- 向导主流程只依赖“端/选择/目录/适配器”抽象。
- 新增语言、框架、依赖时，不改主流程；只新增目录条目、模板、适配器、测试。
- 适配器接口至少包含：planFiles(selection)、planCommands(selection)、parseResult(result)。
- 目录与模板版本独立于插件版本，但随插件发布；报告记录两者版本。

### FR-14 环境扫描、工具链复用与国内镜像

#### FR-14.1 全环境扫描

- 技术栈与依赖管理器选定后，先扫描本机与 DSH 运行时，不立即下载。
- 扫描范围：
  - DSH 自带运行时（node/pnpm/python 及其版本）。
  - PATH、JAVA_HOME、MAVEN_HOME、GRADLE_HOME、NVM/PYENV/SDKMAN 等配置。
  - node、npm、pnpm、yarn、python、pip、uv、poetry、java、javac、mvn、gradle 的实际路径与版本。
  - 项目版本文件（.nvmrc、.python-version、.java-version、.tool-versions）。
  - 代理、npm/pip/maven 配置、镜像配置。
  - npm/PyPI/Maven 仓库连通性、沙箱写权限与提权状态。
- 扫描只读；不写项目文件。

#### FR-14.2 复用优先级

- 优先级：DSH 自带运行时 > 项目内 .specgate/toolchains > 系统 PATH/配置。
- 版本不一致时复用已找到的版本并给出警告，不静默替换。
- 只有缺失或明确不兼容时才进入下载/安装。

#### FR-14.3 工具链供给

- 默认安装到项目内 .specgate/toolchains，沙箱可写，不需要提权。
- 缺失 Maven 3.9.11 / Gradle 8.14 / JDK 11、13、17、21 / uv 时，从国内镜像下载或安装；JDK 8 的 exe 安装包需要系统安装/提权，显示明确错误。
- 下载后必须校验可执行文件与版本；校验失败不继续生成。
- 有提权且显式选择 system scope 时，才允许写入系统环境；默认不修改系统。
- 安装产物写入 .gitignore，不提交二进制。

#### FR-14.4 国内镜像

- 默认启用国内镜像，不访问官方海外源：
  - npm/pnpm：https://registry.npmmirror.com
  - PyPI：清华 https://pypi.tuna.tsinghua.edu.cn/simple 或阿里云 https://mirrors.aliyun.com/pypi/simple/
  - Maven：https://maven.aliyun.com/repository/public
  - Gradle 发行版：https://mirrors.cloud.tencent.com/gradle/
  - JDK 11/13/17/21：https://mirrors.huaweicloud.com/openjdk/
- 生成可编辑配置文件：
  - .specgate/mirrors/npmrc
  - .specgate/mirrors/pip.ini
  - .specgate/mirrors/settings.xml
  - .specgate/mirrors/init.gradle
  - .specgate/mirrors/uv.toml
- 环境变量 SG_MIRROR 可选 aliyun/tsinghua；SG_NPM_REGISTRY、SG_PYPI_INDEX、SG_MAVEN_MIRROR、SG_GRADLE_MIRROR、SG_JDK_MIRROR 可覆盖单项。
- 执行器必须把镜像配置注入 npm/pip/uv/maven/gradle 命令；不能只依赖用户全局配置。

#### FR-14.5 审批页

- 审批页增加一行环境摘要：复用哪些运行时、将下载哪些包管理器、使用哪个镜像。
- 下载/安装仍受最终审批控制；未批准则只生成代码。
- 环境扫描/下载失败时给出可操作错误（缺哪个工具、哪个镜像、哪条命令），不输出泛化的“安装失败”。

## 7. 验收标准

- AC-1 Java 选择 JDK 8/11/13 时，Boot 3.x/4.x 不可选；选 Boot 3.x/4.x 时，JDK 8/11/13 不可选；JDK 13 显示非 LTS 警告。
- AC-2 Java 选择 JDK 21 + Boot 2.7 时，只有在目录存在已验证 patch 时才允许，否则禁用并说明原因。
- AC-3 Python 选择 2.7 时，显示 EOL 警告；FastAPI 不可选；只允许 Flask 1.1.4/Django 1.11.29；不生成 pyproject/uv/Poetry。
- AC-4 Python 3.12 默认可用；FastAPI/Flask/Django 分别生成对应必选依赖、Health、Item CRUD 与测试。
- AC-5 Node 默认 Node 22 + pnpm + TypeScript；Express/Fastify/NestJS 分别生成对应必选依赖；NestJS 下 JavaScript 不可选。
- AC-6 前端 Vue/React + Vite 可选 TS/JS；必选依赖齐全；Next/Nuxt/Angular/Svelte 不出现。
- AC-7 必选依赖锁定不可取消；可选依赖支持最小/推荐/全量预设与逐项调整；互斥组不能同时选。
- AC-8 修改上游选择后，失效的可选依赖被移除并在汇总页列出原因，不静默丢失。
- AC-9 审批页按 api/web 分组，紧凑列出语言/运行时、构建工具、框架、必选/可选依赖与插件；不展开完整命令；有“批准并执行/跳过/返回修改”。
- AC-10 批准后按 install → format → lint → test → review 执行；review 只记录，不阻塞。
- AC-11 未批准/关闭/超时/无问答器时，不执行任何安装或质量命令；仍生成完整声明、配置、代码与测试；报告 quality.status=skipped。
- AC-12 模拟安装失败或测试失败：该端后续阶段停止，另一端继续；init 返回 ok=true、degraded=true；代码照常提交；报告含失败命令与退出码。
- AC-13 模板缺失、目录损坏、git 提交失败等硬失败返回 ok=false，并保留报告与现场。
- AC-14 重复 init 不重复提交、不覆盖用户文件；部分初始化只补缺失项。
- AC-15 断网时选择与生成成功；批准安装失败时进入 degraded，不挂起。

## 9. 风险与待确认

1. 兼容矩阵需按官方支持范围复核：Spring Boot 2.7 与 JDK 21、Boot 4 与 JDK 17、NestJS 与 Node 24、Django 与 Python 3.13 等。目录中必须锁定已验证 patch。
2. Python 2.7 已 EOL：pip/TLS、旧包索引、旧质量工具都可能不可用；只能尽力保证生成，不承诺安装成功。
3. Spring Boot 4.x 的 API/插件生态与 3.x 有差异，模板可能需要独立分支；需在目录中区分。
4. Node 24 与 NestJS 的兼容性需验证；必要时限制 NestJS 的 Node 版本范围。
5. 目录维护成本高；版本漂移、可选依赖冲突、模板与目录不同步是主要风险。
6. 审批页已加 20 行/1200 字符硬限制；仍需在窄屏、长依赖名、双端组合下验证不溢出。
7. 可选依赖只生成声明与最小配置，用户可能误以为功能已实现；报告必须明确边界。
8. 质量命令可能依赖本机工具链（Maven/JDK/Node/Python），工具缺失时进入 degraded；需要在环境预检中提示。
9. “自动化走查”的具体实现（静态规则/AI reviewer）尚未定；本期只要求产出报告且不阻塞，具体 reviewer 可插拔。
10. 现有 v4 代码存在 approved 未传入 buildWorkspace 的问题；已修复并补测试。
11. v4 init 已移除功能/非功能/约束/验收四问；v3 init 保持原行为。
12. 非交互模式的参数设计（preset/--with-quality 等）尚未定；本期只要求“无问答器默认跳过”，不新增复杂 CLI。
13. Python 的 Poetry/uv 选择会生成 pyproject.toml，但 4.1 执行器统一用 pip + requirements.txt 安装同一组依赖；完整 Poetry/uv 安装命令留到后续版本。
